## 들어가며: 4장의 진자는 왜 목표에 못 미쳤을까요?

4장 4.6절에서 진자에 position 액추에이터를 달고 60도로 가라고 했더니, 흔들림 없이 멈추기는 했는데 자리가 목표보다 낮았습니다. kp=5면 30.9도, kp=20이면 49.3도, kp=100이면 57.6도였죠. 1장에서 점 로봇을 목표에 정확히 데려간 바로 그 비례 제어인데, 진자에서는 왜 모자랄까요?

빨랫줄을 떠올려 보세요. 빨래를 널면 줄은 처집니다. 줄을 더 팽팽하게 당기면 덜 처지지만, 아무리 당겨도 완전히 곧게 펴지지는 않아요. 줄이 위로 버티는 힘은 **처진 만큼만** 생기기 때문입니다. 처짐이 0이 되면 버티는 힘도 0이 되니, 빨래 무게만큼은 반드시 처져 있어야 하죠. 비례 제어도 똑같습니다. 모터가 내는 힘이 "목표와의 차이 × kp"라서, 중력을 버티려면 그만큼의 차이가 남아 있어야 해요. 정말 그런지 4장의 숫자를 식으로 다시 계산해 보겠습니다.

```python
import numpy as np
from scipy.optimize import brentq

목표 = np.deg2rad(60)


def 중력_토크(각도: float) -> float:
    """4장 진자(0.5m 막대 끝 1kg 추, 막대 0.01kg)를 아래로 돌리려는 중력 토크(N·m)."""
    return 9.81 * (1.0 * 0.5 + 0.01 * 0.25) * np.sin(각도)


for kp, 잰_값_도 in [(5, 30.9), (20, 49.3), (100, 57.6)]:
    # 용수철이 미는 힘 kp × (목표 - 각도)와 중력 토크가 비기는 각도를 찾는다
    멈춘_각도 = brentq(lambda 각도: kp * (목표 - 각도) - 중력_토크(각도), 0, 목표)
    print(f"kp={kp:3d}: 식으로 {np.rad2deg(멈춘_각도):4.1f}도, 4장에서 잰 값 {잰_값_도}도"
          f" → 처짐 {60 - np.rad2deg(멈춘_각도):4.1f}도, 그때 모터 토크 {중력_토크(멈춘_각도):.2f}N·m")
```

```text
kp=  5: 식으로 30.9도, 4장에서 잰 값 30.9도 → 처짐 29.1도, 그때 모터 토크 2.54N·m
kp= 20: 식으로 49.3도, 4장에서 잰 값 49.3도 → 처짐 10.7도, 그때 모터 토크 3.74N·m
kp=100: 식으로 57.6도, 4장에서 잰 값 57.6도 → 처짐  2.4도, 그때 모터 토크 4.16N·m
```

용수철 힘과 중력 토크가 비기는 각도를 풀었더니 4장에서 시뮬레이션으로 잰 30.9도, 49.3도, 57.6도가 그대로 나왔습니다. 처짐은 시뮬레이터의 오차가 아니라 비례 제어의 성질이에요. 마지막 열을 보면, kp를 20배로 키워도 모터는 여전히 4N·m 남짓을 내며 중력과 버티고 있습니다. 그 힘을 내려면 kp=100에서도 2.4도의 차이가 필요해요.

그래서 P만으로는 부족한 이유가 세 가지 생깁니다.

1. **처짐**: 중력처럼 늘 같은 쪽으로 미는 힘이 있으면 오차가 남는다
2. **흔들림**: 4장에서 감쇠 없이 kp만 줬을 때 진자가 끝없이 오갔다
3. **힘의 한계**: 처짐을 줄이려고 kp를 키우면 출발할 때 엄청난 힘을 요구한다

이 장에서는 이 세 문제를 하나씩 풀어 가며 **PID 제어**를 직접 만듭니다. 1장 Q&A에서 예고했듯이 PID는 P에 I(적분)와 D(미분)를 더한 것이에요. 산업 현장의 온도 조절기부터 드론, 로봇 팔의 관절까지 지금도 가장 많이 쓰이는 제어 방법입니다. 마지막 실습에서는 세로로 선 2관절 팔이 짐을 들고도 목표 자세를 정확히 따라가게 만들어요.

> **Q. PID는 얼마나 오래된 방법인가요?**
> 배의 자동 조타 장치를 연구하던 니콜라스 미노르스키가 1922년에 세 항의 꼴을 정리한 논문을 냈고, 1942년에는 지글러와 니콜스가 이득을 고르는 처방을 발표했습니다(12.8절에서 써 봅니다). 백 년 가까이 쓰인 이유는 단순함이에요. 로봇의 정확한 수학 모델을 몰라도 오차 하나만 보고 동작하고, 세 숫자만 고르면 됩니다. 16장에서 만날 MPC처럼 모델을 써서 앞을 내다보는 방법들도 결국 맨 안쪽 고리에서는 PID가 관절을 붙잡고 있는 경우가 많아요.

## 12.1 오차 하나, 질문 셋

### 옆바람 부는 길에서 차선 지키기

차를 몰며 차선 한가운데를 지킨다고 해 봅시다. 목표는 차선 가운데이고, 지금 차가 가운데에서 벗어난 거리가 **오차**예요. 운전자는 이 오차 하나를 보고 세 가지를 생각합니다.

- **지금 얼마나 벗어났나?** 많이 벗어났으면 핸들을 많이 꺾는다. 이것이 **P(비례)**
- **얼마나 빠르게 벗어나고 있나?** 가운데로 빠르게 돌아오는 중이면 미리 핸들을 풀어 지나치지 않게 한다. 이것이 **D(미분)**
- **그동안 계속 한쪽으로 밀려 왔나?** 옆바람이 늘 오른쪽에서 분다면 핸들을 왼쪽으로 조금 꺾은 채로 둔다. 이것이 **I(적분)**

P는 현재를, D는 앞으로를, I는 지나온 과거를 봅니다. 셋을 더한 것이 PID 제어의 출력이에요.

> 출력 = kp × 오차 + ki × (오차를 시간으로 쌓은 값) + kd × (오차가 변하는 빠르기)

옆바람이 바로 들어가며의 중력입니다. 늘 같은 쪽으로 미는 힘이죠. 운전자가 바람을 이기려고 핸들을 꺾은 채로 두는 것처럼, I 항이 오차를 쌓아 가며 버티는 힘을 만들어 줍니다.

### 실험대: 모터 하나로 돌리는 진자

세 항을 하나씩 실험할 장면이 필요합니다. 4장 4.6절과 같은 진자(0.5m 막대 끝에 1kg 추)인데, 이번에는 position 액추에이터 대신 **motor 액추에이터**를 답니다. motor는 받은 토크를 그대로 내니, 제어는 전부 우리가 짠 파이썬 코드가 맡게 돼요. 진짜 로봇에서 관절 제어기를 짜는 것과 같은 처지입니다. 다음 내용을 `진자장면.py`로 저장하세요.

```python
"""12장: 모터 하나로 돌리는 진자. 각도 0은 똑바로 아래, 단위는 rad와 N·m."""
from collections.abc import Callable

import mujoco
import numpy as np

XML = """
<mujoco>
  <option timestep="0.001"/>
  <worldbody>
    <body pos="0 0 1">
      <joint name="pivot" type="hinge" axis="0 1 0" damping="0.02"/>
      <geom type="capsule" fromto="0 0 0 0 0 -0.5" size="0.01" mass="0.01"/>
      <geom type="sphere" pos="0 0 -0.5" size="0.04" mass="1"/>
    </body>
  </worldbody>
  <actuator><motor name="모터" joint="pivot" ctrlrange="-50 50"/></actuator>
</mujoco>
"""


def 실행(제어기: Callable, 목표: float | Callable[[float], float], 시간: float = 3.0,
       주기: float = 0.01, 잡음: float = 0.0, 토크_한계: float = 50.0,
       시드: int = 0) -> dict[str, np.ndarray]:
    """주기마다 각도를 재서 제어기(목표, 잰_각도)에 묻고, 받은 토크를 다음 주기까지 그대로 준다."""
    모델 = mujoco.MjModel.from_xml_string(XML)
    모델.actuator_ctrlrange[0] = [-토크_한계, 토크_한계]     # 모터가 낼 수 있는 토크의 범위
    데이터 = mujoco.MjData(모델)
    생성기 = np.random.default_rng(시드)
    한_주기_걸음 = round(주기 / 모델.opt.timestep)
    기록 = {"시각": [], "목표": [], "각도": [], "잰_각도": [], "요청": [], "토크": []}
    for k in range(round(시간 / 주기)):
        t = k * 주기
        목표값 = 목표(t) if callable(목표) else 목표
        각도 = 데이터.qpos[0]
        잰_각도 = 각도 + 생성기.normal(0, 잡음) if 잡음 > 0 else 각도
        요청 = 제어기(목표값, 잰_각도)
        데이터.ctrl[0] = 요청                  # 한계를 넘는 몫은 MuJoCo가 ctrlrange로 자른다
        실제 = float(np.clip(요청, -토크_한계, 토크_한계))
        for 이름, 값 in zip(기록, [t, 목표값, 각도, 잰_각도, 요청, 실제]):
            기록[이름].append(값)
        for _ in range(한_주기_걸음):
            mujoco.mj_step(모델, 데이터)
    return {이름: np.array(값) for 이름, 값 in 기록.items()}
```

`실행` 함수는 1장의 감지·판단·행동 고리 그대로입니다. 제어 주기마다 각도를 재고(잡음을 더할 수도 있어요), 제어기에게 토크를 묻고, 그 토크를 다음 주기까지 그대로 준 채 MuJoCo를 진행시켜요. 시뮬레이션 걸음은 0.001초, 제어 주기는 기본 0.01초(100Hz)라서 한 주기에 걸음 10번이 지나갑니다. 1장 1.4절 표에서 관절 제어가 수백 Hz ~ 1kHz라고 했으니 조금 느린 편이에요. 이 느림이 무슨 일을 하는지도 12.5절에서 봅니다.

모터가 낼 수 있는 토크에는 한계가 있습니다. `ctrlrange`가 그 범위인데, 이 범위를 넘는 명령을 넣으면 MuJoCo는 `ctrl` 값은 그대로 두고 실제 힘만 한계로 잘라요(100을 넣어 보니 `ctrl`은 100, `actuator_force`는 한계값이었습니다). 그래서 기록에는 제어기가 **요청**한 토크와 모터가 실제로 낸 **토크**를 따로 남깁니다. 기본 한계는 50N·m로 넉넉하게 잡았고, 12.6절에서 작은 모터로 바꿔 볼 거예요.

### 기본 PID 코드

이제 PID를 코드로 옮깁니다. 컴퓨터는 연속된 시간이 아니라 주기마다 한 번씩 계산하니, 적분은 "오차 × 주기"를 더해 나가는 것으로, 미분은 "이번 오차 - 지난 오차"를 주기로 나누는 것으로 바꿉니다. 다음 내용을 `피아이디.py`로 저장하세요.

```python
"""12장: 가장 기본적인 이산 시간 PID. 제어 주기마다 한 번씩 부른다."""


class PID:
    def __init__(self, kp: float, ki: float, kd: float, 주기: float):
        self.kp, self.ki, self.kd, self.주기 = kp, ki, kd, 주기
        self.적분 = 0.0                 # 지금까지 쌓인 오차 × 시간
        self.이전_오차 = None           # 미분을 위해 한 주기 전 오차를 기억한다

    def __call__(self, 목표: float, 측정: float) -> float:
        오차 = 목표 - 측정
        self.적분 += 오차 * self.주기
        미분 = 0.0 if self.이전_오차 is None else (오차 - self.이전_오차) / self.주기
        self.이전_오차 = 오차
        return self.kp * 오차 + self.ki * self.적분 + self.kd * 미분
```

열 줄 남짓이에요. 처음 불릴 때는 지난 오차가 없으니 미분을 0으로 둡니다. 객체로 만든 이유는 적분과 지난 오차를 **기억**해야 하기 때문이에요. 1권 11장에서 본 `__call__` 덕분에 `제어기(목표, 측정)`처럼 함수처럼 부를 수 있습니다.

### 계단 응답을 숫자 넷으로

제어기를 비교하려면 "잘 따라간다"를 숫자로 말할 수 있어야 합니다. 가장 흔한 시험은 목표를 한순간에 바꿔 놓고 따라가는 모습을 보는 **계단 응답(step response)** 이에요. 계단 응답을 읽는 네 가지 지표가 있습니다.

| 지표 | 뜻 | 좋은 쪽 |
|---|---|---|
| 상승 시간 | 변화량의 10%에서 90%까지 가는 데 걸린 시간 | 짧을수록 빠르다 |
| 오버슈트 | 목표를 넘어간 가장 큰 양(변화량에 대한 %) | 작을수록 얌전하다 |
| 정착 시간 | 목표의 ±2% 띠 안에 들어가 다시는 나오지 않게 된 시각 | 짧을수록 좋다 |
| 정상 상태 오차 | 다 자리 잡은 뒤에도 남는 차이 | 0이 목표 |

라이브러리에 맡겨도 되지만, 기록 배열에서 직접 계산하면 각 지표의 뜻이 분명해집니다. 다음 내용을 `계단지표.py`로 저장하세요.

```python
"""12장: 계단 응답의 네 가지 지표를 기록에서 직접 계산한다."""
import numpy as np


def 계단_지표(시각: np.ndarray, 값: np.ndarray, 시작값: float, 목표값: float,
          띠: float = 0.02) -> dict[str, float]:
    """상승 시간(10%→90%), 오버슈트(%), 정착 시간(±2% 띠), 정상 상태 오차를 돌려준다.

    오차는 목표값 - 값이고, 정상 상태 오차는 마지막 10% 구간의 평균이다.
    정착하지 못했거나 90%에 닿지 못했으면 그 지표는 nan이다.
    """
    변화 = 목표값 - 시작값
    진행 = (값 - 시작값) / 변화                       # 0에서 출발해 1이 목표
    지표 = {"상승": np.nan, "오버슈트": max(진행.max() - 1, 0.0) * 100, "정착": np.nan}
    if (진행 >= 0.9).any():
        지표["상승"] = 시각[np.argmax(진행 >= 0.9)] - 시각[np.argmax(진행 >= 0.1)]
    밖 = np.abs(진행 - 1) > 띠
    if not 밖[-1]:                                    # 마지막에 띠 안이어야 정착한 것
        지표["정착"] = 시각[np.flatnonzero(밖)[-1] + 1] if 밖.any() else 시각[0]
    지표["오차"] = float(np.mean(목표값 - 값[-max(len(값) // 10, 1):]))
    return 지표


def 지표_글(지표: dict[str, float]) -> str:
    """표에 넣기 좋게 도 단위 한 줄로."""
    def 초(x: float) -> str:
        return "   -  " if np.isnan(x) else f"{x:5.2f}초"
    return (f"상승 {초(지표['상승'])}  오버슈트 {지표['오버슈트']:5.1f}%  "
            f"정착 {초(지표['정착'])}  정상 오차 {np.rad2deg(지표['오차']) + 0.0:6.2f}도")
```

## 12.2 P: 지금 틀린 만큼 밀기

### 4장의 position 액추에이터가 바로 P

먼저 확인할 것이 있습니다. 4장의 position 액추에이터는 "kp × (목표 - 각도)"의 힘을 냈죠. 그럼 우리 P 제어기를 motor에 붙인 것과 같을까요? 제어기를 시뮬레이션 걸음마다 부르면(주기 0.001초) 둘이 정확히 같아야 합니다.

```python
import mujoco
import numpy as np

from 진자장면 import XML, 실행
from 피아이디 import PID

목표 = np.deg2rad(60)
# 우리 P 제어기를 시뮬레이션 걸음마다(0.001초) 부르고, 토크 한계는 사실상 없앤다
우리_것 = 실행(PID(kp=20, ki=0, kd=0, 주기=0.001), 목표, 시간=3.0, 주기=0.001, 토크_한계=1e6)

# 같은 진자에 4장의 position 액추에이터(kp=20)를 단다
xml = XML.replace('<motor name="모터" joint="pivot" ctrlrange="-50 50"/>',
                  '<position name="모터" joint="pivot" kp="20"/>')
모델 = mujoco.MjModel.from_xml_string(xml)
데이터 = mujoco.MjData(모델)
데이터.ctrl[0] = 목표
위치_액추에이터 = []
for _ in range(3000):
    위치_액추에이터.append(데이터.qpos[0])
    mujoco.mj_step(모델, 데이터)

차이 = np.abs(np.array(위치_액추에이터) - 우리_것["각도"]).max()
print(f"3초 동안 두 진자 각도의 가장 큰 차이: {np.rad2deg(차이):.1e}도")
print(f"각도 범위: {np.rad2deg(우리_것['각도'].min()) + 0.0:.1f}도 ~ {np.rad2deg(우리_것['각도'].max()):.1f}도")
```

```text
3초 동안 두 진자 각도의 가장 큰 차이: 3.8e-14도
각도 범위: 0.0도 ~ 100.2도
```

3초 동안 3000걸음 내내 두 진자의 각도 차이가 1e-13도보다 작습니다. 컴퓨터의 반올림 오차뿐이니 완전히 같은 움직임이에요. position 액추에이터는 MuJoCo 안에 들어 있는 P 제어기였던 겁니다. 각도가 0도에서 100.2도 사이를 오간 것도 4장 그림과 같아요. 감쇠가 없으니 지나쳤다 돌아오기를 되풀이합니다.

정리하면, P만으로는 처짐도 남고 흔들림도 잡히지 않습니다. 흔들림부터 잡아 봅시다.

## 12.3 D: 변하는 빠르기를 보고 미리 브레이크

### 오차가 줄어드는 빠르기

진자가 목표를 향해 빠르게 다가오고 있다면, 오차는 빠르게 줄어들고 있습니다. 이때 P는 "아직 멀었다"며 계속 밀지만, 운전자라면 이미 브레이크를 밟기 시작할 거예요. D 항은 **오차가 변하는 빠르기**에 kd를 곱합니다. 오차가 줄어드는 중이면 미분이 음수라서 P의 힘을 깎아 주고, 지나쳐서 오차가 반대로 커지는 중이면 되돌리는 힘을 보태요. 목표가 그대로일 때 오차의 변화 빠르기는 각속도에 마이너스를 붙인 것과 같으니, D는 관절에 **감쇠기**를 단 것과 같습니다. 4장의 `dampratio`가 MuJoCo 안에서 하던 일이 바로 이거예요.

얼마나 줘야 할까요? 용수철(kp)과 감쇠기(kd)를 단 물체가 흔들림 없이 가장 빠르게 멈추는 kd를 **임계 감쇠**라고 하고, 관성 J에 대해 kd = 2√(J × 단단함)입니다. `dampratio="1"`이 바로 이 값을 넣어 주는 설정이었어요. 진자의 J를 MuJoCo에게 묻고, kd를 바꿔 가며 확인해 봅시다.

```python
import matplotlib.pyplot as plt
import mujoco
import numpy as np

from 진자장면 import XML, 실행
from 피아이디 import PID

plt.rcParams["font.family"] = "AppleGothic"
plt.rcParams["axes.unicode_minus"] = False

# 진자의 관성 모멘트 J를 MuJoCo에게 묻는다(관절 공간의 질량 행렬, 여기서는 1×1)
모델 = mujoco.MjModel.from_xml_string(XML)
데이터 = mujoco.MjData(모델)
mujoco.mj_forward(모델, 데이터)
질량_행렬 = np.zeros((1, 1))
mujoco.mj_fullM(모델, 데이터, 질량_행렬)
J = 질량_행렬[0, 0]
kp = 30
중력_용수철 = 9.81 * 0.5025 * np.cos(np.deg2rad(60))      # 60도 근처에서 중력이 더하는 용수철 효과
임계_kd = 2 * np.sqrt(J * (kp + 중력_용수철))
print(f"J = {J:.4f} kg·m², 흔들림이 딱 사라지는 kd ≈ {임계_kd:.2f}")

목표 = np.deg2rad(60)
그림, 칸 = plt.subplots(figsize=(7, 3.4))
for kd in [0, 1, 3, round(임계_kd, 1), 12]:
    기록 = 실행(PID(kp, 0, kd, 주기=0.01), 목표, 시간=3.0)
    각도_도 = np.rad2deg(기록["각도"])
    멈춘 = 각도_도[-50:].mean()                              # 마지막 0.5초의 평균
    밖 = np.abs(각도_도 - 멈춘) > 1.0
    자리_잡음 = f"{기록['시각'][np.flatnonzero(밖)[-1] + 1]:.2f}초" if not 밖[-1] else "  못 함"
    print(f"kd={kd:4.1f}: 가장 높이 {각도_도.max():5.1f}도, 끝 {멈춘:5.1f}도, 끝 ±1도 안에 자리 잡음 {자리_잡음}")
    칸.plot(기록["시각"], 각도_도, label=f"kd={kd}")
칸.axhline(60, color="gray", linestyle="--", linewidth=1)
칸.set_xlabel("시간(초)")
칸.set_ylabel("각도(도)")
칸.set_ylim(-60, 160)
칸.legend(fontsize=8, ncol=5, loc="upper center")
그림.tight_layout()
그림.savefig("add_d.png", dpi=200)
print("저장: add_d.png")
```

```text
J = 0.2515 kg·m², 흔들림이 딱 사라지는 kd ≈ 5.71
kd= 0.0: 가장 높이 150.2도, 끝  43.6도, 끝 ±1도 안에 자리 잡음   못 함
kd= 1.0: 가장 높이  85.5도, 끝  52.5도, 끝 ±1도 안에 자리 잡음 2.00초
kd= 3.0: 가장 높이  60.2도, 끝  52.5도, 끝 ±1도 안에 자리 잡음 0.64초
kd= 5.7: 가장 높이  52.5도, 끝  52.5도, 끝 ±1도 안에 자리 잡음 0.53초
kd=12.0: 가장 높이  52.5도, 끝  52.5도, 끝 ±1도 안에 자리 잡음 1.37초
저장: add_d.png
```

![kp=30에 kd를 0, 1, 3, 5.7, 12로 바꾼 결과. kd=0은 흔들림이 점점 커지고, kd=1은 몇 번 출렁이다 멈추며, kd=3은 살짝 넘었다 멈추고, kd=5.7은 넘지 않고 가장 빨리 자리 잡으며, kd=12는 너무 천천히 다가간다. 모두 60도가 아니라 52.5도에 멈춘다.](../assets/images/ch12/add_d.png)

`mj_fullM`은 관절 공간의 질량 행렬(관절이 하나면 관성 모멘트 J)을 채워 주는 함수예요. MuJoCo 3.17에서는 `mj_fullM(모델, 데이터, 행렬)` 순서로 부릅니다. J = 0.2515kg·m²는 1kg 추가 0.5m 거리에 있으니 1 × 0.5² = 0.25에 막대와 추 크기 몫이 조금 더해진 값이에요. 단단함에는 kp=30에 60도 근처에서 중력이 더하는 복원력 2.46을 보탰더니 임계 kd는 5.71이 나왔습니다.

결과가 이 계산과 맞습니다. kd=0은 앞 절처럼 흔들림이 커지고, kd=1은 85.5도까지 넘었다가 출렁이며 2초 만에 자리 잡고, kd=3은 60.2도까지 살짝 넘습니다. 임계 값 kd=5.7은 한 번도 넘지 않고 0.53초 만에 자리를 잡아 가장 빨랐어요. 더 키운 kd=12는 오히려 1.37초로 느려졌습니다. 감쇠가 너무 세면 꿀 속에서 움직이듯 굼떠지거든요. 하지만 모두 52.5도에 멈췄습니다. D는 흔들림을 잡을 뿐, 처짐에는 손을 대지 못해요. 멈춘 뒤에는 오차가 변하지 않으니 D 항이 0이기 때문입니다.

> **Q. D 항은 왜 브레이크라고 하나요?**
> 목표가 고정돼 있으면 D 항은 -kd × 각속도입니다. 움직이는 쪽과 반대 방향으로, 빠를수록 세게 미는 힘이에요. 자동차의 브레이크나 문에 달린 도어 클로저의 유압 장치가 하는 일과 같습니다. 그래서 진짜 로봇의 관절 제어기는 각도를 미분하는 대신 엔코더에서 잰 각속도를 바로 쓰기도 해요. 12.10절의 계단식 제어가 그런 예입니다.

## 12.4 I: 쌓인 오차로 끈질기게

### 처진 만큼 계속 쌓기

이제 처짐을 없앨 차례입니다. I 항은 오차를 시간으로 쌓은 값에 ki를 곱해요. 진자가 52.5도에 멈춰 있으면 7.5도의 오차가 매 주기 쌓이니 I 항이 조금씩 커지고, 그만큼 진자를 더 들어 올립니다. 오차가 0이 될 때까지 쌓기를 멈추지 않으니, 결국 오차가 0인 곳에서만 멈출 수 있어요. 그때 I 항에 남는 값이 바로 중력을 버티는 데 필요한 토크입니다. 빨랫줄 비유로 말하면, 처진 줄을 누군가 처짐이 사라질 때까지 조금씩 더 들어 올려 주는 거예요.

I 항이 넘어가게 만드는 이유는 **과거를 보기 때문**입니다. 올라가는 동안 쌓아 둔 오차가 목표에 닿은 순간에도 그대로 남아 있어서, 오차가 0인데도 계속 밀거든요. 넘어간 다음에야 반대쪽 오차로 쌓인 것을 갚아 나갑니다. 그래서 ki는 "처짐을 얼마나 빨리 지우느냐"와 "얼마나 넘어가느냐"를 맞바꾸는 손잡이예요. 세 항의 역할을 표로 모아 두겠습니다.

| 항 | 보는 것 | 키우면 좋아지는 것 | 키우면 나빠지는 것 |
|---|---|---|---|
| P | 지금의 오차 | 빨라지고 처짐이 준다 | 흔들림이 커진다 |
| I | 쌓인 오차 | 정상 상태 오차가 0이 된다 | 넘어가고 느리게 출렁인다 |
| D | 오차의 변화 빠르기 | 흔들림과 넘어감이 준다 | 잡음에 민감해지고 너무 크면 굼뜨다 |

### 주기를 곱하고 나누는 이유

`피아이디.py`는 적분에 주기를 곱하고 미분을 주기로 나눴습니다. 이걸 빼고 "한 박자당" 값으로 이득을 적는 구현도 흔해요. 7장에서 본 서보처럼 작은 마이크로컨트롤러는 나눗셈을 아끼려고 그렇게 짜기도 합니다. 100Hz에서 똑같이 움직이도록 맞춘 두 구현을 200Hz로 옮겨 보겠습니다.

```python
import numpy as np

from 계단지표 import 계단_지표, 지표_글
from 진자장면 import 실행
from 피아이디 import PID


class 박자PID:
    """주기를 곱하고 나누지 않는 PID. 이득이 '한 박자당' 값이라 주기가 바뀌면 뜻이 달라진다."""

    def __init__(self, kp: float, ki_박자: float, kd_박자: float):
        self.kp, self.ki_박자, self.kd_박자 = kp, ki_박자, kd_박자
        self.적분, self.이전_오차 = 0.0, None

    def __call__(self, 목표: float, 측정: float) -> float:
        오차 = 목표 - 측정
        self.적분 += 오차                               # 주기를 곱하지 않는다
        미분 = 0.0 if self.이전_오차 is None else 오차 - self.이전_오차   # 주기로 나누지 않는다
        self.이전_오차 = 오차
        return self.kp * 오차 + self.ki_박자 * self.적분 + self.kd_박자 * 미분


목표 = np.deg2rad(60)
kp, ki, kd = 30, 30, 5.7
# 100Hz에서 똑같이 움직이도록 맞춘 '한 박자당' 이득
ki_박자, kd_박자 = ki * 0.01, kd / 0.01
for 주기 in [0.01, 0.005]:
    for 이름, 제어기 in [("주기를 쓰는 PID", PID(kp, ki, kd, 주기)), ("박자 이득 PID ", 박자PID(kp, ki_박자, kd_박자))]:
        기록 = 실행(제어기, 목표, 시간=4.0, 주기=주기)
        print(f"{1 / 주기:3.0f}Hz {이름}: " + 지표_글(계단_지표(기록["시각"], 기록["각도"], 0.0, 목표)))
```

```text

100Hz 박자 이득 PID : 상승  0.29초  오버슈트   2.9%  정착  1.35초  정상 오차  -0.08도
```

100Hz에서는 두 구현이 한 자리도 다르지 않습니다. 그런데 200Hz로 옮기자 주기를 쓰는 PID는 지표가 거의 그대로인데, 박자 이득 PID는 오버슈트가 2.9%에서 24.1%로 뛰었어요. 박자가 두 배 잦아지니 적분은 두 배 빨리 쌓이고 미분은 절반이 됐기 때문입니다. 남이 튜닝한 이득을 가져오거나 제어 주기를 바꿀 때는 **이득의 단위에 시간이 들어 있는지** 꼭 확인하세요. 이 책의 PID는 초 단위 이득을 씁니다.

## 12.6 출력 포화와 적분 와인드업

### 모터는 무한히 세지 않다

지금까지 모터 한계를 50N·m로 넉넉하게 잡았습니다. 하지만 7장에서 본 STS3215 같은 취미용 서보는 그보다 훨씬 약하고, 산업용 팔도 관절마다 한계가 있어요. 한계에 걸리는 것을 **출력 포화(saturation)** 라고 합니다. 포화 자체는 어쩔 수 없지만, PID에게는 고약한 부작용이 하나 있습니다.

모터가 한계까지 힘을 내도 진자가 천천히 올라가는 동안, 오차는 크게 남아 있으니 I 항은 계속 쌓입니다. 모터는 이미 최대인데 적분만 하염없이 커지는 거예요. 진자가 목표에 닿았을 때 I 항에는 엄청난 값이 쌓여 있어서, 이걸 다 갚을 때까지 진자는 목표를 한참 넘어갑니다. 태엽을 너무 감아 놓은 것 같다고 해서 **적분 와인드업(windup)** 이라고 불러요.

막는 방법은 두 가지가 흔합니다.

- **클램핑(조건부 적분)**: 출력이 한계에 걸려 있고 오차가 포화를 더 깊게 만드는 쪽이면 그 주기에는 쌓지 않는다
- **역계산(back-calculation)**: 요청과 실제 출력의 차이(잘려 나간 몫)에 비례해 적분을 되돌린다

다음 몇 절에서 쓸 장치들을 모두 갖춘 PID를 `실전PID.py`로 저장하겠습니다. 와인드업 방지 말고도 12.7절의 측정값 미분과 미분 필터, 12.9절의 앞먹임과 적분 분리가 함께 들어 있어요. 지금은 `와인드업` 부분만 보면 됩니다.

```python
"""12장: 와인드업 방지, 측정값 미분, 미분 필터, 출력 한계, 앞먹임을 갖춘 PID."""
import numpy as np


class 실전PID:
    def __init__(self, kp: float, ki: float, kd: float, 주기: float, 출력_한계: float = np.inf,
                 와인드업: str = "클램핑", 미분_대상: str = "측정", 필터_알파: float = 1.0,
                 적분_구간: float = np.inf):
        self.kp, self.ki, self.kd, self.주기 = kp, ki, kd, 주기
        self.출력_한계, self.와인드업, self.미분_대상 = 출력_한계, 와인드업, 미분_대상
        self.필터_알파 = 필터_알파          # 1이면 거르지 않는다. 작을수록 많이 거른다
        self.적분_구간 = 적분_구간          # 오차가 이 안에 들어왔을 때만 적분한다(rad)
        # 역계산 이득: 적분 시간과 미분 시간의 기하 평균을 쓰는 흔한 관례
        적분_시간 = kp / ki if ki > 0 else np.inf
        미분_시간 = kd / kp if kd > 0 else 적분_시간
        self.역계산_이득 = 1 / np.sqrt(적분_시간 * 미분_시간)
        self.적분항 = 0.0                  # ki × (오차의 적분)을 바로 담는다
        self.거른_값 = None                # 미분할 신호를 1차 저역통과로 거른 값

    def __call__(self, 목표: float, 측정: float, 앞먹임: float = 0.0) -> float:
        오차 = 목표 - 측정
        대상 = -측정 if self.미분_대상 == "측정" else 오차      # 목표가 그대로면 둘의 변화는 같다
        if self.거른_값 is None:
            self.거른_값, 미분 = 대상, 0.0
        else:
            새_값 = self.거른_값 + self.필터_알파 * (대상 - self.거른_값)
            미분 = (새_값 - self.거른_값) / self.주기
            self.거른_값 = 새_값
        요청 = self.kp * 오차 + self.적분항 + self.kd * 미분 + 앞먹임
        출력 = float(np.clip(요청, -self.출력_한계, self.출력_한계))
        쌓을_오차 = 오차 if abs(오차) <= self.적분_구간 else 0.0
        if self.와인드업 == "없음":
            self.적분항 += self.ki * 쌓을_오차 * self.주기
        elif self.와인드업 == "클램핑":             # 포화를 더 깊게 만드는 쪽으로는 쌓지 않는다
            if 출력 == 요청 or np.sign(쌓을_오차) != np.sign(요청):
                self.적분항 += self.ki * 쌓을_오차 * self.주기
        else:                                        # 역계산: 잘려 나간 만큼 적분을 되돌린다
            self.적분항 += (self.ki * 쌓을_오차 + self.역계산_이득 * (출력 - 요청)) * self.주기
        return 출력
```

기본 `PID`와 달라진 점은 적분을 `적분항`에 **ki를 곱한 값**으로 쌓는다는 것이에요. 그래야 한계(N·m)와 바로 비교할 수 있고, 역계산에서 잘려 나간 토크를 그대로 빼 줄 수 있습니다. 역계산의 되돌리는 빠르기(`역계산_이득`)는 적분 시간과 미분 시간의 기하 평균을 쓰는 흔한 관례를 따랐어요.

### 꼭대기를 넘어가는 진자

모터 한계를 6N·m로 줄이고, 진자를 거의 꼭대기인 150도로 보내 보겠습니다. 90도에서 중력 토크가 4.93N·m이니 6N·m짜리 모터는 겨우겨우 들어 올려요. 감싸개 `적분항도_적기`는 매 주기 적분항을 함께 기록하려고 만든 것입니다.

```python
import matplotlib.pyplot as plt
import numpy as np

from 계단지표 import 계단_지표, 지표_글
from 실전PID import 실전PID
from 진자장면 import 실행

plt.rcParams["font.family"] = "AppleGothic"
plt.rcParams["axes.unicode_minus"] = False


def 적분항도_적기(제어기: 실전PID, 적분항들: list[float]):
    """제어기를 부를 때마다 적분항을 함께 기록하는 감싸개."""
    def 호출(목표값: float, 측정: float) -> float:
        토크 = 제어기(목표값, 측정)
        적분항들.append(제어기.적분항)
        return 토크
    return 호출


목표, 한계 = np.deg2rad(150), 6.0               # 거의 꼭대기까지, 6N·m짜리 작은 모터로

for 방식 in ["없음", "클램핑", "역계산"]:

    적분항 = []
    기록 = 실행(적분항도_적기(제어기, 적분항), 목표, 시간=5.0, 토크_한계=한계)
    print(f"{방식:4s}: " + 지표_글(계단_지표(기록["시각"], 기록["각도"], 0.0, 목표))
          + f", 가장 높이 {np.rad2deg(기록['각도'].max()):5.1f}도, 적분항 최대 {max(적분항):5.1f}N·m")
    위.plot(기록["시각"], np.rad2deg(기록["각도"]), label=f"와인드업 방지: {방식}")
    아래.plot(기록["시각"], 적분항, label=방식)
위.axhline(150, color="gray", linestyle="--", linewidth=1)
위.axhline(180, color="black", linestyle=":", linewidth=1)
위.set_ylabel("각도(도)")
위.legend(fontsize=8, loc="lower right")
아래.axhline(한계, color="gray", linestyle="--", linewidth=1)
아래.set_ylabel("적분항(N·m)")
아래.set_xlabel("시간(초)")
그림.tight_layout()
그림.savefig("windup.png", dpi=200)
print("저장: windup.png")
```

## 12.7 미분 킥과 미분 잡음

### 목표가 바뀌는 순간의 발길질

D 항은 오차의 변화 빠르기를 봅니다. 그런데 목표를 30도에서 60도로 확 바꾸면 어떻게 될까요? 그 한 주기 동안 오차가 30도(0.52rad)나 변하니, 미분은 0.52 ÷ 0.01 = 52rad/s라는 터무니없는 값이 됩니다. 여기에 kd=5.7을 곱하면 약 300N·m, P 항까지 더하면 300N·m가 넘는 토크를 한 주기 동안 요청해요. 이렇게 목표가 바뀌는 순간 D 항이 걷어차듯 튀는 것을 **미분 킥(derivative kick)** 이라고 합니다.

고치는 방법은 간단합니다. 목표가 그대로일 때는 오차의 변화와 측정값의 변화가 부호만 다르니, 오차 대신 **측정값을 미분**하면 돼요. 측정값은 목표가 바뀌어도 순간이동하지 않으니까요. `실전PID`의 `미분_대상`이 이 선택입니다.

```python
import matplotlib.pyplot as plt
import numpy as np

from 실전PID import 실전PID
from 진자장면 import 실행

plt.rcParams["font.family"] = "AppleGothic"
plt.rcParams["axes.unicode_minus"] = False


def 목표(t: float) -> float:
    """30도에 있다가 1.5초에 60도로 바꾼다."""
    return np.deg2rad(30 if t < 1.5 else 60)


그림, (위, 아래) = plt.subplots(2, 1, figsize=(7, 4.6), sharex=True)
for 대상, 이름 in [("오차", "오차를 미분"), ("측정", "측정값을 미분")]:
    기록 = 실행(실전PID(30, 30, 5.7, 주기=0.01, 미분_대상=대상), 목표, 시간=2.5)
    바뀐_뒤 = 기록["시각"] >= 1.5
    print(f"{이름}: 목표가 바뀐 순간 요청 토크 {기록['요청'][바뀐_뒤][0]:6.1f}N·m, "
          f"모터가 실제로 낸 가장 큰 토크 {기록['토크'][바뀐_뒤].max():4.1f}N·m")
    위.plot(기록["시각"], np.rad2deg(기록["각도"]), label=이름)
    아래.plot(기록["시각"], 기록["요청"], label=이름)
위.plot(기록["시각"], np.rad2deg(기록["목표"]), color="gray", linestyle="--", linewidth=1, label="목표")
위.set_ylim(25, 68)
위.set_ylabel("각도(도)")
위.legend(fontsize=8, loc="lower right")
아래.set_ylabel("요청 토크(N·m)")
아래.set_xlabel("시간(초)")
아래.set_xlim(1.3, 2.5)
그림.tight_layout()
그림.savefig("derivative_kick.png", dpi=200)
print("저장: derivative_kick.png")
```

### 잡음을 키우는 미분

D 항의 약점이 하나 더 있습니다. 측정에 잡음이 있으면, 미분은 잡음의 "변화"를 주기로 나누니 잡음이 엄청나게 커져요. 7장에서 본 4096눈금 엔코더라면 한 눈금(0.088도) 차이만으로도 100Hz에서 0.15rad/s의 가짜 속도가 생깁니다. 각도 센서에 표준편차 0.5도의 잡음을 넣어 보겠습니다.

해결책은 10장 10.7절에서 키포인트 떨림을 줄일 때 쓴 **1차 저역통과 필터**입니다. 미분하기 전에 측정값을 새 값 쪽으로 알파만큼만 다가가게 걸러요. 8장의 상보 필터에서 본 것처럼 알파는 시간 상수로 읽을 수 있습니다. 알파가 작을수록 오래된 값을 오래 기억하는 필터예요.

```python

from 실전PID import 실전PID
from 진자장면 import 실행

목표 = np.deg2rad(60)
잡음 = np.deg2rad(0.5)                       # 각도 센서의 잡음(표준편차 0.5도)
주기 = 0.01

    뒤 = 기록["시각"] >= 2.0                   # 자리 잡은 뒤 2초 동안의 떨림(표준편차)

          f"{np.rad2deg(기록['각도'][뒤].std()):6.3f}도 | "
```

## 12.8 튜닝: 이득은 어떻게 고르나

### 손으로 맞추는 순서

이득 세 개를 고르는 일을 **튜닝**이라고 합니다. 모델을 몰라도 쓸 수 있는 손 튜닝 순서가 널리 쓰여요. 이 장의 실험을 거꾸로 따라가는 셈입니다.

| 단계 | 할 일 | 볼 것 |
|---|---|---|
| 1 | ki, kd를 0으로 두고 kp를 작게 시작해 키운다 | 빨라지다가 흔들리기 시작하는 지점 |
| 2 | kd를 키워 흔들림을 잡는다 | 넘어감이 거의 사라지는 지점(너무 크면 굼뜨고 잡음) |
| 3 | 1~2를 오가며 kp를 조금 더 키운다 | 모터 한계·잡음이 허락하는 데까지 |
| 4 | ki를 작게 시작해 키운다 | 정상 오차가 원하는 시간 안에 사라지는 지점(넘어감 주의) |
| 5 | 큰 목표, 작은 목표, 짐을 든 경우로 다시 시험한다 | 포화와 와인드업, 다른 조건에서의 흔들림 |

로봇 관절에서는 2단계가 특히 중요합니다. 12.2절에서 봤듯이 마찰이 작은 관절은 P만으로는 늦음 때문에 흔들림이 커지니, D를 일찍 넣어야 해요. 진짜 로봇에서 튜닝할 때는 처음에 토크 한계를 낮게 걸고, 손을 비상 정지 버튼에 두고 시작하세요(1장 1.7절).

### 지글러-니콜스 맛보기

1942년의 **지글러-니콜스(Ziegler-Nichols) 방법**은 실험 두 번으로 이득을 정하는 처방입니다.

1. P만 두고 kp를 키워, 흔들림이 줄지도 커지지도 않고 **같은 폭으로 계속되는** 이득 Ku와 그때의 흔들림 주기 Tu를 잰다
2. 표에 넣는다: P는 kp = 0.5Ku, PI는 kp = 0.45Ku와 ki = 0.54Ku/Tu, PID는 kp = 0.6Ku, ki = 1.2Ku/Tu, kd = 0.075Ku·Tu

이 방법은 원래 공장의 온도·유량처럼 반응이 굼뜨고 지연이 있는 공정을 위해 만들어졌습니다. 그런데 우리 진자는 12.2절에서 봤듯이 P만 줘도 흔들림이 조금씩 커지는, "계속 같은 폭으로 흔들리는 이득"이 거의 0에 붙어 있는 대상이에요. 그래서 맛보기에는 1장 1.4절의 점 로봇을 다시 데려오겠습니다. 측정이 0.1초 늦게 도착하고, 바람이 늘 뒤로 0.2m/s씩 밀어서 P만으로는 처짐이 남는 직선 위의 점이에요.

```python
import numpy as np

주기, 늦음 = 0.02, 0.1                     # 50Hz, 측정이 0.1초 늦게 도착한다(1장 1.4절의 점 로봇)
늦은_박자 = round(늦음 / 주기)


def 달리기(kp: float, ki: float, kd: float, 초: float = 10.0, 바람: float = -0.2) -> np.ndarray:
    """1m 앞 목표로 가는 1차원 점 로봇. 바람이 늘 -0.2m/s로 민다. 위치 기록을 돌려준다."""
    기록, 적분, 이전_오차 = [0.0], 0.0, None
    for _ in range(round(초 / 주기)):
        오차 = 1.0 - 기록[max(len(기록) - 1 - 늦은_박자, 0)]   # 늦게 도착한 측정으로 판단
        적분 += 오차 * 주기
        미분 = 0.0 if 이전_오차 is None else (오차 - 이전_오차) / 주기
        이전_오차 = 오차
        속도 = kp * 오차 + ki * 적분 + kd * 미분
        기록.append(기록[-1] + (속도 + 바람) * 주기)
    return np.array(기록)


def 커지는_비율(kp: float) -> float:
    """P만으로 달렸을 때 뒤쪽 흔들림 폭 ÷ 앞쪽 흔들림 폭. 1이면 꼭 같은 폭으로 계속 흔들린다."""
    x = 달리기(kp, 0, 0, 초=20, 바람=0.0)
    n = len(x)
    return np.ptp(x[3 * n // 4:]) / np.ptp(x[n // 4:n // 2])


# 1단계: P 이득을 키워 가며 흔들림이 줄지도 커지지도 않는 '한계 이득' Ku를 찾는다(이분 탐색)
아래, 위 = 1.0, 40.0
for _ in range(40):
    가운데 = (아래 + 위) / 2
    아래, 위 = (아래, 가운데) if 커지는_비율(가운데) > 1 else (가운데, 위)
Ku = (아래 + 위) / 2
x = 달리기(Ku, 0, 0, 초=20, 바람=0.0)
올라가며_지남 = np.flatnonzero(np.diff(np.sign(x[500:] - 1.0)) > 0)   # 목표를 아래에서 위로 지나는 박자
Tu = np.mean(np.diff(올라가며_지남)) * 주기
print(f"한계 이득 Ku = {Ku:.2f}, 흔들림 주기 Tu = {Tu:.2f}초")

# 2단계: 지글러-니콜스 표에 넣는다
처방 = {"P": (0.5 * Ku, 0, 0), "PI": (0.45 * Ku, 0.54 * Ku / Tu, 0),
        "PID": (0.6 * Ku, 1.2 * Ku / Tu, 0.075 * Ku * Tu)}
for 이름, (kp, ki, kd) in 처방.items():
    x = 달리기(kp, ki, kd)
    밖 = np.abs(x - 1.0) > 0.02
    정착 = f"{(np.flatnonzero(밖)[-1] + 1) * 주기:.2f}초" if not 밖[-1] else "  못 함"
    print(f"{이름:3s}: kp={kp:5.2f} ki={ki:5.2f} kd={kd:4.2f} → 가장 멀리 {x.max():.3f}m, "
          f"끝 {x[-1]:.3f}m, ±2cm 정착 {정착}")
```

```text
한계 이득 Ku = 14.23, 흔들림 주기 Tu = 0.44초
P  : kp= 7.12 ki= 0.00 kd=0.00 → 가장 멀리 1.250m, 끝 0.972m, ±2cm 정착   못 함
PI : kp= 6.40 ki=17.47 kd=0.00 → 가장 멀리 1.695m, 끝 1.000m, ±2cm 정착 1.26초
PID: kp= 8.54 ki=38.81 kd=0.47 → 가장 멀리 1.737m, 끝 1.000m, ±2cm 정착 1.04초
```

이분 탐색으로 찾은 Ku는 14.23, Tu는 0.44초입니다. 연속 시간에서 지연 d만 있는 적분 대상이면 Ku = π/(2d) ≈ 15.7, Tu = 4d = 0.4초인데, 50Hz 박자의 늦음이 조금 더해져 그보다 약간 작은 이득에서 흔들렸어요.

처방대로 넣은 결과가 지글러-니콜스의 성격을 잘 보여 줍니다. P는 바람 때문에 끝에 0.972m로 처졌고(정착 못 함), PI와 PID는 처짐을 지우고 1초 남짓에 정착했지만 1.7m 안팎까지, 즉 70% 안팎이나 넘어갔어요. 이 처방은 흔들림이 한 번 출렁일 때마다 4분의 1로 줄어드는 공격적인 응답을 노리고 만들어졌기 때문입니다. 그래서 지글러-니콜스는 **출발점**으로 쓰고, 넘어감이 싫으면 kp와 ki를 줄여 가며 다듬습니다.

### 시뮬레이션으로 이득 표 훑기

시뮬레이터가 있으면 더 직접적인 방법이 있습니다. 이득 조합을 잔뜩 돌려 보고 표로 보는 거예요. 진짜 로봇으로는 수십 번의 계단 응답이 부담스럽지만 시뮬레이션은 몇 초면 끝납니다. 칸을 줄이려고 ki = kp로 묶고, kp와 kd 두 축만 훑겠습니다.

```python
plt.rcParams["axes.unicode_minus"] = False

kd들 = [1, 2, 3, 4, 6, 8, 10]
정착 = np.full((len(kp들), len(kd들)), np.nan)

가장_빠른 = np.unravel_index(np.nanargmin(정착), 정착.shape)
조건 = np.where(오버슈트 <= 5, 정착, np.nan)                  # 오버슈트 5% 이하만

그림, 칸 = plt.subplots(figsize=(7, 4))
그림판 = 칸.imshow(정착, cmap="viridis_r", vmin=0, vmax=3, origin="lower")
for i in range(len(kp들)):

        칸.text(j, i, 글, ha="center", va="center", fontsize=7,
               color="black" if np.isnan(정착[i, j]) or 정착[i, j] < 1.5 else "white")
칸.set_xticks(range(len(kd들)), kd들)
칸.set_yticks(range(len(kp들)), kp들)
칸.set_xlabel("kd")
칸.set_ylabel("kp (ki = kp)")
그림.colorbar(그림판, label="정착 시간(초)")
그림.tight_layout()
그림.savefig("gain_grid.png", dpi=200)
print("저장: gain_grid.png")
```

## 12.9 피드포워드: 아는 힘은 미리 주기

### 모르는 척하지 말자

PID는 오차가 생겨야 움직이는 "뒷북" 제어입니다. 중력이 진자를 당기는 건 이미 알고 있는데, 처지고 나서야 I 항이 천천히 알아채게 할 필요가 있을까요? 무거운 짐을 들어 올릴 때 사람은 팔이 처지기 전에 미리 힘을 줍니다. 이렇게 오차를 보지 않고 **미리 아는 만큼 먼저 넣는** 것을 **피드포워드(feedforward, 앞먹임)** 라고 해요. 오차를 보고 고치는 피드백과 짝을 이룹니다.

중력 토크는 들어가며에서 식으로 계산했지만, 팔이 복잡해지면 식을 손으로 세우기 어렵습니다. MuJoCo는 지금 자세에서 관절에 걸리는 중력(과 움직임이 만드는 힘)을 `qfrc_bias`에 계산해 둬요. 4장 4.3절의 `mj_forward`로 자세만 정해 계산하면 됩니다. 식과 같은지, 그만큼 밀어 주면 정말 떠 있는지 확인해 봅시다.

```python
import mujoco
import numpy as np

from 진자장면 import XML

모델 = mujoco.MjModel.from_xml_string(XML)
데이터 = mujoco.MjData(모델)
for 각도_도 in [0, 30, 60, 90, 150]:
    데이터.qpos[0], 데이터.qvel[0] = np.deg2rad(각도_도), 0.0
    mujoco.mj_forward(모델, 데이터)                            # 지금 자세에서 힘들을 계산만 한다
    식 = 9.81 * (1.0 * 0.5 + 0.01 * 0.25) * np.sin(np.deg2rad(각도_도))   # 들어가며의 중력_토크
    print(f"{각도_도:3d}도: qfrc_bias {데이터.qfrc_bias[0]:6.3f}N·m, 식 {식:6.3f}N·m")

# qfrc_bias만큼 모터로 밀어 주면 진자는 그 자리에 떠 있을까?
데이터.qpos[0], 데이터.qvel[0] = np.deg2rad(60), 0.0
for _ in range(2000):                                         # 2초
    mujoco.mj_forward(모델, 데이터)
    데이터.ctrl[0] = 데이터.qfrc_bias[0]
    mujoco.mj_step(모델, 데이터)
print(f"2초 동안 qfrc_bias만 줬을 때 각도: {np.rad2deg(데이터.qpos[0]):.4f}도")
```

```text

150도: qfrc_bias  2.465N·m, 식  2.465N·m

```

다섯 각도 모두 `qfrc_bias`가 식과 소수 셋째 자리까지 같고, 그만큼을 모터로 계속 밀어 주자 진자는 2초 동안 60.0000도에 그대로 떠 있었습니다. 부호도 확인됐어요. `qfrc_bias`는 "버티려면 관절에 줘야 할 힘" 쪽 부호라서 그대로 `ctrl`에 넣으면 됩니다. 30도와 150도가 같은 2.465N·m인 것도 sin 30° = sin 150°이니 맞아요.

### 앞먹임과 적분은 사이가 나쁘다

이제 PID 출력에 목표 자세의 중력 토크를 더해 봅시다. 진짜 로봇에서는 모델이 완벽하지 않으니, 질량을 80%로 잘못 안 경우도 넣었어요. 그리고 마지막 두 줄에는 `실전PID`의 **적분 분리**(오차가 5도 안에 들어왔을 때만 적분하기)를 썼습니다.

```python
import mujoco
import numpy as np

from 계단지표 import 계단_지표, 지표_글
from 실전PID import 실전PID
from 진자장면 import XML, 실행


def 중력_계산기(질량_배율: float = 1.0):
    """진자 모델로 각도마다 qfrc_bias를 계산하는 함수. 질량_배율로 모델이 틀린 경우를 흉내 낸다."""
    모델 = mujoco.MjModel.from_xml_string(XML)
    모델.body_mass[1:] *= 질량_배율
    데이터 = mujoco.MjData(모델)

    def 중력(각도: float) -> float:
        데이터.qpos[0], 데이터.qvel[0] = 각도, 0.0
        mujoco.mj_forward(모델, 데이터)
        return float(데이터.qfrc_bias[0])
    return 중력


def 앞먹임_붙이기(제어기: 실전PID, 중력):
    """목표 자세를 버티는 데 드는 토크를 미리 계산해 PID 출력에 더한다."""
    return lambda 목표값, 측정: 제어기(목표값, 측정, 앞먹임=중력(목표값))


목표 = np.deg2rad(60)
분리 = np.deg2rad(5)                       # 적분 분리: 오차가 5도 안일 때만 적분한다
경우들 = {
    "PD                         ": 실전PID(30, 0, 5.7, 0.01),
    "PD + 앞먹임                 ": 앞먹임_붙이기(실전PID(30, 0, 5.7, 0.01), 중력_계산기()),
    "PD + 앞먹임(질량 80%)        ": 앞먹임_붙이기(실전PID(30, 0, 5.7, 0.01), 중력_계산기(0.8)),
    "PID                        ": 실전PID(30, 30, 5.7, 0.01),
    "PID + 앞먹임(질량 80%)       ": 앞먹임_붙이기(실전PID(30, 30, 5.7, 0.01), 중력_계산기(0.8)),
    "PID + 적분 분리              ": 실전PID(30, 30, 5.7, 0.01, 적분_구간=분리),
    "PID + 적분 분리 + 앞먹임(80%) ": 앞먹임_붙이기(실전PID(30, 30, 5.7, 0.01, 적분_구간=분리),
                                       중력_계산기(0.8)),
}
for 이름, 제어기 in 경우들.items():
    기록 = 실행(제어기, 목표, 시간=4.0)
    print(f"{이름}: " + 지표_글(계단_지표(기록["시각"], 기록["각도"], 0.0, 목표)))
```

- **PD**: 처짐 7.47도. 12.3절 그대로다
- **PD + 앞먹임**: 처짐이 0이 되고 0.53초에 정착한다. 넘어감도 없다. 모델이 완벽하면 I가 필요 없다
- **PD + 앞먹임(질량 80%)**: 모델이 틀린 20%만큼 다시 처진다(1.50도). 앞먹임만으로는 모델 오차를 못 고친다
- **PID**: 처짐은 없지만 1.39초가 걸린다
- **PID + 앞먹임(질량 80%)**: 오히려 나빠졌다. 9.8% 넘어가고 2.23초
- **PID + 적분 분리**: 정착하지 못한다. 처짐 7.47도가 분리 구간 5도보다 커서 적분이 아예 시작되지 않는다
- **PID + 적분 분리 + 앞먹임(80%)**: 넘어감 0%, 0.75초, 오차 0.02도. 가장 좋다

다섯째 줄이 흥미롭습니다. 앞먹임을 더했는데 왜 나빠졌을까요? 앞먹임 덕분에 진자는 더 빨리 올라가는데, I 항은 그 사이에도 "올라가는 동안의 큰 오차"를 쌓습니다. 중력은 앞먹임이 이미 버티고 있으니 그 적분은 쓸 데가 없는 빚이 되어 넘어감을 만들어요. 12.6절의 와인드업과 같은 모양입니다. 그래서 앞먹임을 쓸 때는 적분이 **목표 근처의 작은 오차(모델이 틀린 몫)만** 맡도록 분리하면 둘의 장점이 함께 살아납니다. 반대로 앞먹임 없이 적분 분리만 쓰면 여섯째 줄처럼 큰 처짐 앞에서 적분이 일을 시작조차 못 하니, 분리는 앞먹임과 짝으로 써야 해요.

## 12.10 계단식 제어: 고리 안의 고리

### 위치는 바깥에서, 속도는 안쪽에서

1장 1.4절에서 "안쪽 고리일수록 빠르고, 바깥쪽 고리일수록 느리지만 똑똑한 일을 한다"고 했습니다. 이 생각을 제어기 하나 안에서 쓰는 것이 **계단식(cascade) 제어**예요. 바깥 고리는 위치 오차를 보고 "이 빠르기로 가라"는 **목표 속도**를 내고, 안쪽 고리가 그 속도를 맞추는 토크를 냅니다. 회사로 치면 팀장이 "이번 주에 이만큼"을 정하고, 실무자가 매일 그 속도를 맞추는 셈이에요.

좋은 점이 두 가지 있습니다. 바깥 고리가 내는 목표 속도를 자르면 **최대 속도가 저절로 지켜지고**(7장 7.7절에서 목표를 5도씩 잘라 보낸 것과 같은 효과), 중력 같은 방해는 빠른 안쪽 고리가 위치 오차로 번지기 전에 잡아냅니다. 산업용 서보 드라이브는 대개 전류(힘) → 속도 → 위치의 세 겹으로 되어 있어요. 진자를 120도로 보내면서 PID 하나와 비교해 봅시다. 안쪽 고리는 MuJoCo가 주는 각속도(`qvel`)를 씁니다. 진짜 모터라면 엔코더 값을 미분하거나 드라이버가 잰 속도를 받아요.

```python
import matplotlib.pyplot as plt
import mujoco
import numpy as np

from 실전PID import 실전PID
from 진자장면 import XML

plt.rcParams["font.family"] = "AppleGothic"
plt.rcParams["axes.unicode_minus"] = False

목표 = np.deg2rad(120)
최대_속도 = 2.0                           # 바깥 고리가 내줄 수 있는 가장 빠른 속도(rad/s)


def 계단식(시간: float = 3.0) -> dict[str, np.ndarray]:
    """바깥: 50Hz 위치 P → 목표 속도. 안쪽: 500Hz 속도 PI → 토크."""
    모델 = mujoco.MjModel.from_xml_string(XML)
    데이터 = mujoco.MjData(모델)
    속도_제어기 = 실전PID(10.0, 200.0, 0.0, 주기=0.002, 출력_한계=50.0)
    기록 = {"시각": [], "각도": [], "속도": [], "목표_속도": []}
    for k in range(round(시간 / 0.002)):
        if k % 10 == 0:                                    # 0.02초마다 바깥 고리
            목표_속도 = np.clip(5.0 * (목표 - 데이터.qpos[0]), -최대_속도, 최대_속도)
        데이터.ctrl[0] = 속도_제어기(목표_속도, 데이터.qvel[0])   # 0.002초마다 안쪽 고리
        for 이름, 값 in zip(기록, [k * 0.002, 데이터.qpos[0], 데이터.qvel[0], 목표_속도]):
            기록[이름].append(값)
        for _ in range(2):
            mujoco.mj_step(모델, 데이터)
    return {이름: np.array(값) for 이름, 값 in 기록.items()}


def 한_고리(시간: float = 3.0) -> dict[str, np.ndarray]:
    """비교: 100Hz 위치 PID 하나로 토크를 바로 정한다."""
    모델 = mujoco.MjModel.from_xml_string(XML)
    데이터 = mujoco.MjData(모델)
    제어기 = 실전PID(30, 30, 5.7, 주기=0.01, 출력_한계=50.0)
    기록 = {"시각": [], "각도": [], "속도": []}
    for k in range(round(시간 / 0.01)):
        데이터.ctrl[0] = 제어기(목표, 데이터.qpos[0])
        for 이름, 값 in zip(기록, [k * 0.01, 데이터.qpos[0], 데이터.qvel[0]]):
            기록[이름].append(값)
        for _ in range(10):
            mujoco.mj_step(모델, 데이터)
    return {이름: np.array(값) for 이름, 값 in 기록.items()}


그림, (위, 아래) = plt.subplots(2, 1, figsize=(7, 4.6), sharex=True)
for 이름, 기록 in [("PID 하나", 한_고리()), ("계단식(위치 P → 속도 PI)", 계단식())]:
    각도_도 = np.rad2deg(기록["각도"])
    print(f"{이름}: 가장 빠를 때 {np.abs(기록['속도']).max():.2f}rad/s, 가장 높이 {각도_도.max():6.2f}도, "
          f"끝 {각도_도[-1]:6.2f}도")
    위.plot(기록["시각"], 각도_도, label=이름)
    아래.plot(기록["시각"], 기록["속도"], label=이름)
아래.plot(기록["시각"], 기록["목표_속도"], color="gray", linestyle="--", linewidth=1, label="바깥 고리가 준 목표 속도")
위.axhline(120, color="gray", linestyle="--", linewidth=1)
위.set_ylabel("각도(도)")
위.legend(fontsize=8, loc="lower right")
아래.set_ylabel("각속도(rad/s)")
아래.set_xlabel("시간(초)")
아래.legend(fontsize=8, loc="upper right")
그림.tight_layout()
그림.savefig("cascade.png", dpi=200)
print("저장: cascade.png")
```

```text
계단식(위치 P → 속도 PI): 가장 빠를 때 2.41rad/s, 가장 높이 120.00도, 끝 120.00도
저장: cascade.png
```

![120도 계단에서 PID 하나와 계단식 제어의 각도와 각속도. PID 하나는 순간 8.8rad/s까지 휘둘러 129도까지 넘어가고, 계단식은 2rad/s 근처의 일정한 속도로 곧게 올라가 넘지 않고 120도에 선다.](../assets/images/ch12/cascade.png)

PID 하나는 출발하자마자 8.80rad/s로 휘둘러 129.43도까지 넘어갔고, 3초 뒤에도 120.46도로 아직 돌아오는 중이에요. 계단식은 출발 직후 잠깐 2.41rad/s까지 나간 뒤 바깥 고리가 정한 2rad/s를 지키며 곧은 선으로 올라가, 목표 근처에서 속도를 줄여 120.00도에 섭니다. 각도 그래프가 비스듬한 직선인 구간이 "최대 속도로 가는 중"이에요. 올라가는 동안 중력이 계속 바뀌는데도 속도가 일정한 건, 안쪽 고리가 500Hz로 그 변화를 바로바로 메웠기 때문입니다.

계단식의 대가는 고리가 두 개라 이득도 두 벌이라는 것이에요. 튜닝은 **안쪽부터** 합니다. 안쪽 고리가 바깥보다 충분히(보통 다섯 배 이상) 빠르게 반응해야 바깥 고리가 안쪽을 "시키는 대로 하는 부하"로 볼 수 있어요. 여기서는 박자도 500Hz와 50Hz로 열 배 차이를 뒀습니다.

## 12.11 여러 관절: 관절마다 PID, 그리고 간섭

### 세로로 선 2관절 팔

이제 관절이 둘인 팔로 넘어갑니다. 4장 실습의 팔(위팔 0.30m, 아래팔 0.25m)과 같은 구조인데, 이번에는 **세로로** 세워서 두 관절 모두 중력을 받게 했어요. 손끝에는 0.4kg 공이 달려 있고, 관절마다 motor 액추에이터를 답니다. 진짜 감속기처럼 관절 마찰(`damping`)을 0.5로 키웠어요. 다음 내용을 `세로팔.py`로 저장하세요.

```python
"""12장 실습: 세로로 선 평면 2관절 팔. 각도 0은 수평, 양수는 위로 드는 쪽."""
from collections.abc import Callable

import mujoco
import numpy as np

L1, L2 = 0.30, 0.25                      # 위팔·아래팔 길이(m), 4장 실습 팔과 같다
토크_한계 = np.array([20.0, 8.0])        # 어깨·팔꿈치 모터가 낼 수 있는 토크(N·m)


def 장면(짐: float = 0.0) -> str:
    """손끝에 짐(kg)을 든 팔의 MJCF. 받침 원통은 팔과 부딪히지 않게 충돌을 끈다."""
    return f"""
<mujoco model="세로 2관절 팔">
  <option timestep="0.001" integrator="implicitfast"/>
  <asset>
    <texture type="skybox" builtin="gradient" rgb1="0.95 0.95 1" rgb2="0.6 0.7 0.8" width="256" height="256"/>
  </asset>
  <default><joint type="hinge" axis="0 -1 0" damping="0.5"/></default>
  <worldbody>
    <light pos="0 -1.5 2" dir="0 0.6 -1"/>
    <camera name="side" pos="0.1 -1.6 0.75" xyaxes="1 0 0 0 0 1"/>
    <geom type="plane" size="1 1 0.1" rgba="0.85 0.85 0.85 1"/>
    <body name="base" pos="0 0 0.8">
      <geom type="cylinder" fromto="0 0.06 0 0 0.03 0" size="0.04" rgba="0.3 0.3 0.3 1"
            contype="0" conaffinity="0"/>
      <body name="upper">
        <joint name="shoulder"/>
        <geom type="capsule" fromto="0 0 0 {L1} 0 0" size="0.025" mass="1.0" rgba="0.2 0.5 0.9 1"/>
        <body name="lower" pos="{L1} 0 0">
          <joint name="elbow"/>
          <geom type="capsule" fromto="0 0 0 {L2} 0 0" size="0.02" mass="0.6" rgba="0.2 0.7 0.5 1"/>
          <geom type="sphere" pos="{L2} 0 0" size="0.035" mass="{0.4 + 짐}" rgba="0.9 0.3 0.2 1"/>
          <site name="tip" pos="{L2} 0 0"/>
        </body>
      </body>
    </body>
  </worldbody>
  <actuator>
    <motor name="shoulder" joint="shoulder" ctrlrange="-{토크_한계[0]} {토크_한계[0]}"/>
    <motor name="elbow" joint="elbow" ctrlrange="-{토크_한계[1]} {토크_한계[1]}"/>
  </actuator>
</mujoco>
"""


def 실행(제어기들: list[Callable], 목표: Callable[[float], np.ndarray], 시간: float,
       중력_보상: bool = False, 짐: float = 0.0, 주기: float = 0.01,
       시작: tuple[float, float] = (-np.pi / 2, 0.0)) -> dict[str, np.ndarray]:
    """관절마다 제어기(목표, 잰_각도, 앞먹임)를 하나씩 두고 주기마다 토크를 정한다.

    중력_보상이 참이면 짐을 모르는 팔 모델로 계산한 qfrc_bias를 앞먹임으로 더한다.
    """
    모델 = mujoco.MjModel.from_xml_string(장면(짐))            # 진짜 팔(짐을 들었을 수 있다)
    데이터 = mujoco.MjData(모델)
    아는_모델 = mujoco.MjModel.from_xml_string(장면())          # 제어기가 알고 있는 팔
    아는_데이터 = mujoco.MjData(아는_모델)
    데이터.qpos[:] = 시작
    mujoco.mj_forward(모델, 데이터)
    기록 = {"시각": [], "목표": [], "각도": [], "토크": [], "손끝": []}
    for k in range(round(시간 / 주기)):
        t = k * 주기
        목표값 = 목표(t)
        앞먹임 = np.zeros(2)
        if 중력_보상:
            아는_데이터.qpos[:], 아는_데이터.qvel[:] = 데이터.qpos, 데이터.qvel
            mujoco.mj_forward(아는_모델, 아는_데이터)
            앞먹임 = 아는_데이터.qfrc_bias.copy()
        토크 = [제어기(목표값[i], 데이터.qpos[i], 앞먹임[i]) for i, 제어기 in enumerate(제어기들)]
        데이터.ctrl[:] = 토크
        for 이름, 값 in zip(기록, [t, 목표값, 데이터.qpos.copy(), np.clip(토크, -토크_한계, 토크_한계),
                                 데이터.site("tip").xpos[[0, 2]].copy()]):
            기록[이름].append(값)
        for _ in range(round(주기 / 모델.opt.timestep)):
            mujoco.mj_step(모델, 데이터)
        mujoco.mj_forward(모델, 데이터)         # 손끝 위치를 걸음을 마친 상태로 맞춘다
    return {이름: np.array(값) for 이름, 값 in 기록.items()}
```

관절 축을 `0 -1 0`으로 잡아서 각도가 커지면 팔이 위로 들리게 했습니다(0도가 수평, -90도가 늘어뜨린 자세). 3장의 평면 2링크 식과 같은 방향이에요. `실행`은 진자 때와 같은 고리인데 두 가지가 더 있습니다. 관절마다 제어기를 하나씩 두는 것, 그리고 `중력_보상`이 켜지면 12.9절처럼 `qfrc_bias`를 앞먹임으로 더하는 것이에요. 이때 `qfrc_bias`는 **짐을 모르는 팔 모델**(`아는_모델`)로 계산합니다. 진짜 로봇도 손에 무엇을 들었는지 모를 때가 많으니까요.

받침 원통의 `contype="0" conaffinity="0"`은 충돌을 끄는 설정입니다. 처음 만들 때 이것을 빼먹었더니 원통과 위팔이 맞닿아 팔이 이유 없이 떨렸어요. MuJoCo는 부모와 자식 몸체 사이의 충돌을 기본으로 거르는데, 받침처럼 관절 없이 세계에 붙은 몸체는 세계 몸체로 취급돼 이 거르기가 적용되지 않았습니다. 팔이 이상하게 떨리면 `데이터.ncon`으로 뜻밖의 접촉부터 확인하세요. 장면이 맞는지, `qfrc_bias`가 무엇을 담는지 보고 몇 자세를 찍어 봅시다. 프레임을 나란히 놓는 데는 4장의 `그림도구.py`를 가져다 씁니다.

```python

        프레임들.append(렌더러.render())
프레임격자(프레임들, [f"어깨 {a}도, 팔꿈치 {b}도" for a, b in 자세들_도], "arm_poses.png", 열=4)
```

멈춰 있을 때 어깨는 5.628N·m, 팔꿈치는 1.214N·m의 중력을 버텨야 합니다. 어깨는 팔 전체의 무게를, 팔꿈치는 아래팔과 손끝 공만 들고 있으니 어깨가 훨씬 크죠. 같은 자세로 어깨가 3rad/s로 돌고 있으면 팔꿈치 값이 1.548N·m로 커집니다. 빙글빙글 도는 아래팔에 바깥으로 내던지는 원심력이 생겨서예요. 이처럼 `qfrc_bias`는 중력에 **움직임이 만드는 힘**까지 더한 값입니다. 진자는 관절이 하나라서 이런 몫이 없었어요.

### 한 관절이 움직이면 다른 관절이 흔들린다

4장 실습에서 어깨가 돌기 시작하면 팔꿈치가 살짝 튀는 것을 봤습니다. 관절별 PID에서 이 **간섭**이 얼마나 되는지 재 봅시다. 팔꿈치 목표는 줄곧 0도로 두고, 0.5초에 어깨만 늘어뜨린 자세에서 수평으로 들어 올립니다. 어깨는 kp=40, ki=40, kd=4, 팔꿈치는 관성이 훨씬 작으니 kp=15, ki=15, kd=1로 줬어요.

```python
import numpy as np

from 세로팔 import 실행, 토크_한계
from 실전PID import 실전PID


def 목표(t: float) -> np.ndarray:
    """0.5초에 어깨만 -90도(늘어뜨림) → 0도(수평)로 든다. 팔꿈치 목표는 줄곧 0도."""
    return np.deg2rad([-90 if t < 0.5 else 0, 0])


분리 = np.deg2rad(5)
for 이름, 보상 in [("관절별 PID", False), ("관절별 PID + 중력 보상 + 적분 분리", True)]:
    제어기들 = [실전PID(40, 40, 4, 0.01, 출력_한계=토크_한계[0], 적분_구간=분리 if 보상 else np.inf),
             실전PID(15, 15, 1, 0.01, 출력_한계=토크_한계[1], 적분_구간=분리 if 보상 else np.inf)]
    기록 = 실행(제어기들, 목표, 시간=2.5, 중력_보상=보상)
    팔꿈치_도 = np.rad2deg(기록["각도"][:, 1])
    든_뒤 = 기록["시각"] >= 0.5
    print(f"{이름}: 들기 전 팔꿈치 {np.abs(팔꿈치_도[~든_뒤]).max():.2f}도, "
          f"드는 동안 가장 크게 {팔꿈치_도[든_뒤].min():6.2f}도 ~ {팔꿈치_도[든_뒤].max():5.2f}도, "
          f"끝 {팔꿈치_도[-1]:5.2f}도")
```

```text

관절별 PID + 중력 보상 + 적분 분리: 들기 전 팔꿈치 0.00도, 드는 동안 가장 크게 -14.67도 ~  9.42도, 끝 -0.05도
```

어깨가 들리기 전에는 팔꿈치가 정확히 0도였는데, 어깨가 움직이는 동안 -13.88도에서 5.48도까지 휘청였습니다. 팔꿈치의 PID는 자기 목표를 바꾼 적이 없는데도요. 어깨가 위팔을 휙 들어 올리면 아래팔은 관성 때문에 제자리에 남으려 해서, 팔꿈치 입장에서는 누가 아래팔을 잡아당긴 것과 같습니다. 팔꿈치 제어기는 이 힘을 오차가 생긴 다음에야 알아채요.

더 눈여겨볼 것은 둘째 줄입니다. 중력 보상을 켜도 휘청임은 -14.67도에서 9.42도로 줄지 않았어요. 중력 보상은 끝에 남는 오차를 -1.21도에서 -0.05도로 지워 줬지만, 움직이는 동안의 간섭은 대부분 **관성**에서 오기 때문입니다. `qfrc_bias`에는 중력과 원심력은 있어도 "어깨가 가속하는 만큼 아래팔을 미는 힘"은 들어 있지 않아요. 이것까지 미리 넣으려면 관절 가속도와 질량 행렬로 필요한 토크 전체를 계산하는 **계산 토크(computed torque) 제어**가 필요하고, 여러 관절을 한꺼번에 내다보며 명령을 정하는 방법은 16장 MPC에서 맛봅니다. 관절별 PID로 버틸 때의 현실적인 대책은 목표를 계단으로 던지지 말고 부드러운 궤적으로 주는 것이에요. 13장 경로 계획이 그 궤적을 만듭니다.

> **Q. 산업용 로봇 팔도 관절마다 PID를 쓰나요?**
> 대부분 그렇습니다. 감속비가 큰 기어를 쓰면 관절 쪽에서 본 모터의 관성이 커져서, 다른 관절이 미는 힘이 상대적으로 작아지고 관절별 PID가 잘 통해요. 여기에 중력 보상 같은 앞먹임을 더하는 것이 흔한 구성입니다. 빠르고 정밀한 동작이 필요하거나 감속비가 작은 팔(사람과 함께 일하는 협동 로봇 등)에서는 모델 기반 앞먹임의 비중이 커집니다.

## 12.12 실습: 2관절 팔로 목표 자세 따라가기

### 무엇을 비교하나

이 장에서 만든 것을 모아 세로 팔이 목표 자세 네 개를 2초씩 차례로 따라가게 하겠습니다. 늘어뜨린 자세에서 출발해 (-30도, 60도) → (20도, 40도) → (45도, -45도) → (-60도, 30도)로 갑니다. 비교할 제어기는 넷이에요.

1. **P만**: 4장의 position 액추에이터와 같은 것(관절 마찰 덕분에 터지지는 않는다)
2. **PID**: 관절마다 12.6절의 `실전PID`(클램핑, 측정값 미분)
3. **PID + 중력 보상**: 2에 `qfrc_bias` 앞먹임
4. **PID + 중력 보상 + 적분 분리**: 3에 12.9절의 적분 분리(5도)

그리고 손끝에 제어기가 모르는 0.5kg 짐을 달고 한 번 더 돌립니다. 성적은 목표마다 두 관절이 모두 ±2도 안에 들어와 머무른 시각(도착)과, 2초가 끝날 때의 오차로 매깁니다.

```python
import matplotlib.pyplot as plt
import numpy as np

from 세로팔 import 실행, 토크_한계
from 실전PID import 실전PID

plt.rcParams["font.family"] = "AppleGothic"
plt.rcParams["axes.unicode_minus"] = False

목표들 = np.deg2rad([[-30, 60], [20, 40], [45, -45], [-60, 30]])    # (어깨, 팔꿈치)
머무름, 주기 = 2.0, 0.01


def 목표(t: float) -> np.ndarray:
    return 목표들[min(int(t // 머무름), len(목표들) - 1)]


def 제어기들(ki_배율: float, kd_배율: float, 분리: float = np.inf) -> list[실전PID]:
    """어깨(kp 40)와 팔꿈치(kp 15)의 PID. 배율로 I, D를 켜고 끈다."""
    return [실전PID(40, 40 * ki_배율, 4 * kd_배율, 주기, 출력_한계=토크_한계[0], 적분_구간=분리),
            실전PID(15, 15 * ki_배율, 1 * kd_배율, 주기, 출력_한계=토크_한계[1], 적분_구간=분리)]


def 성적(기록: dict) -> tuple[float, float, float]:
    """목표마다 두 관절이 모두 ±2도 안에 들어와 머문 시각과, 머무름이 끝날 때의 오차."""
    오차_도 = np.rad2deg(np.abs(기록["목표"] - 기록["각도"]))
    n = round(머무름 / 주기)
    도착들, 끝_오차 = [], []
    for 구간 in range(len(목표들)):
        조각 = 오차_도[구간 * n:(구간 + 1) * n]
        밖 = 조각.max(axis=1) > 2.0
        도착들.append(np.nan if 밖[-1] else (np.flatnonzero(밖)[-1] + 1) * 주기 if 밖.any() else 0.0)
        끝_오차.append(조각[-1])
    끝 = np.mean(끝_오차, axis=0)
    return np.nanmean(도착들) if not np.isnan(도착들).all() else np.nan, int(np.isnan(도착들).sum()), 끝


경우들 = {"P만": (dict(ki_배율=0, kd_배율=0), False),
        "PID": (dict(ki_배율=1, kd_배율=1), False),
        "PID + 중력 보상": (dict(ki_배율=1, kd_배율=1), True),
        "PID + 중력 보상 + 적분 분리": (dict(ki_배율=1, kd_배율=1, 분리=np.deg2rad(5)), True)}
그림, 칸들 = plt.subplots(2, 1, figsize=(8, 5), sharex=True)
print("제어기                    | 짐   | 평균 도착 | 못 감 | 끝 오차(어깨, 팔꿈치)")
for 이름, (설정, 보상) in 경우들.items():
    for 짐 in [0.0, 0.5]:
        기록 = 실행(제어기들(**설정), 목표, 시간=머무름 * len(목표들), 중력_보상=보상, 짐=짐)
        평균_도착, 못_감, 끝 = 성적(기록)
        도착_글 = "  -  " if np.isnan(평균_도착) else f"{평균_도착:.2f}초"
        print(f"{이름:22s} | {짐:.1f}kg | {도착_글:>8s} | {못_감}/4 | {끝[0]:5.2f}도, {끝[1]:5.2f}도")
        if 짐 == 0.0:
            for j in range(2):
                칸들[j].plot(기록["시각"], np.rad2deg(기록["각도"][:, j]), linewidth=1.2, label=이름)
for j, 관절 in enumerate(["어깨", "팔꿈치"]):
    칸들[j].plot(기록["시각"], np.rad2deg(기록["목표"][:, j]), color="black", linestyle="--",
               linewidth=1, label="목표")
    칸들[j].set_ylabel(f"{관절} 각도(도)")
칸들[0].set_ylim(-150, 70)
칸들[0].legend(fontsize=7, ncol=3, loc="lower left")
칸들[1].set_xlabel("시간(초)")
그림.tight_layout()
그림.savefig("arm_pid_compare.png", dpi=200)
print("저장: arm_pid_compare.png")
```

## 12.13 정리와 다음 장 미리보기

이 장에서 목표를 따라가는 가장 오래된 지혜를 직접 만들고 고쳐 봤습니다.

- **P**: 지금의 오차에 비례해 민다. 중력처럼 늘 미는 힘이 있으면 처짐이 남고(빨랫줄), 키울수록 흔들림이 커진다. MuJoCo의 position 액추에이터가 바로 P 제어기다
- **D**: 오차의 변화 빠르기를 보는 브레이크. 임계 감쇠 kd = 2√(J × 단단함)에서 흔들림 없이 가장 빠르다. 처짐은 못 고친다
- **I**: 쌓인 오차로 처짐을 지운다. 대신 과거를 기억해서 넘어감을 만든다
- **지표**: 상승 시간(10→90%), 오버슈트, 정착 시간(±2% 띠), 정상 상태 오차를 기록에서 직접 계산한다
- **이산 시간**: 적분에는 주기를 곱하고 미분은 주기로 나눈다(이득 단위에 시간이 들어 있는지 확인). 주기가 느리면 반 주기 늦음이 흔들림을 키우고, kd×주기/J가 1을 넘으면 불안정해진다
- **와인드업**: 출력이 포화된 동안 적분이 쌓여 크게 넘어간다. 클램핑이나 역계산으로 막는다
- **미분 킥과 잡음**: 오차 대신 측정값을 미분하고, 1차 저역통과로 거른다. 너무 거르면 늦음 때문에 오히려 불안정해진다
- **튜닝**: 손 튜닝(P → D → I), 지글러-니콜스(Ku와 Tu로 처방, 공격적인 출발점), 시뮬레이션으로 이득 표 훑기(여유 있는 칸을 고른다)
- **피드포워드**: `qfrc_bias`로 중력을 미리 버틴다. 모델 오차는 적분이 메우되, 적분 분리로 둘이 다투지 않게 한다
- **계단식 제어**: 바깥 위치 고리가 목표 속도를, 안쪽 속도 고리가 토크를 낸다. 최대 속도가 저절로 지켜진다. 튜닝은 안쪽부터
- **여러 관절**: 관절별 PID는 간단하지만 관절 사이의 관성 간섭은 오차가 생긴 뒤에야 고친다. 계산 토크 제어, 16장 MPC, 그리고 부드러운 궤적이 대책이다(LQR처럼 모델로 최적 이득을 계산하는 방법도 있다)

이 장의 팔은 목표 자세를 **계단으로** 받았습니다. 그래서 목표가 바뀔 때마다 팔이 휘청이고, 손끝이 어떤 길로 갈지는 제어기의 성격에 맡겨졌어요. 4장 실습에서 손끝이 엉뚱한 곡선을 그렸던 것도 같은 이유였죠. 다음 13장에서는 이 빈자리를 채웁니다. 장애물을 피해 출발점에서 목표까지 가는 길을 찾고(경로 계획), 그 길을 시간에 맞춰 부드럽게 나눠 이 장의 PID에게 건네주는 법을 배워요. 좋은 제어기는 좋은 목표를 받을 때 가장 빛납니다.
