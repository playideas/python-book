## 들어가며: 말로 시키려면 무엇이 필요할까요?

15장의 로봇 팔은 상자를 스무 번 집어 옮겼습니다. 그런데 그때 로봇에게 준 것을 떠올려 보세요. "상자 가운데는 (0.45, 0.15), 요는 30도, 놓을 곳은 (0.3, -0.25)." 전부 숫자였죠. 9장의 카메라도 "빨간 덩어리", "초록 덩어리"처럼 미리 정해 둔 색만 찾을 수 있었고요.

사람은 이렇게 말하지 않습니다. 식탁을 치우는 가족에게 "빨간 상자를 파란 그릇에 넣어 줘"라고 하죠. 이 짧은 말을 로봇이 따르려면 세 가지가 필요합니다.

| 필요한 것 | 지금까지의 방법 | 이 장의 방법 |
|---|---|---|
| 장면에 무엇이 있는지 알기 | 정해 둔 색 범위(9장), 정해 둔 80가지 이름표(9.8절) | 글로 찾을 것을 정하는 검출기, 사진에 묻는 비전-언어 모델 |
| 말이 무엇을 시키는지 알기 | 없음(사람이 숫자를 넣었다) | 규칙, 언어 모델이 정해진 기술의 순서로 바꾸기 |
| 시킨 일을 몸으로 하기 | 15장의 집고-놓기 상태 기계 | 그대로 쓴다. 다만 실행 전에 계획을 검사한다 |

가운데 줄이 새로 생긴 칸입니다. 그리고 첫째 줄도 크게 바뀌어요. "빨간 상자"라는 말을 받아 그 물체를 사진에서 찾으려면, 로봇의 눈이 미리 정한 이름표가 아니라 **말 자체를 알아들어야** 합니다. 이 두 칸을 채우는 것이 요즘 로봇 공학에서 가장 빠르게 바뀌는 부분인 **파운데이션 모델(foundation model)** 이에요.

이 장에서는 이 맥에서 바로 돌아가는 작은 공개 모델로 지시 하나를 끝까지 따라가 봅니다. 사진에 질문하는 모델, 글로 물체를 찾는 모델, 지시를 계획으로 바꾸는 모델을 차례로 써 보고, 각각이 어디까지 믿을 만한지 숫자로 확인할 거예요. 모델이 틀리는 장면도 여러 번 나옵니다. 그래서 모델이 낸 계획을 **실행 전에 검사하는 코드**가 이 장의 숨은 주인공이에요. 그다음 보는 것, 듣는 것, 움직이는 것을 모델 하나로 해내는 VLA를 살펴보고, 마지막 선택 절에서는 Claude에게 계획을 맡겨 봅니다.

> **Q. 큰 모델을 내려받아야 하나요? 상업적으로 써도 되나요?**
> 이 장에서 내려받는 모델은 세 가지이고, 모두 처음 실행할 때 Hugging Face에서 받아 캐시에 둡니다. 비전-언어 모델 SmolVLM-500M-Instruct(약 5억 매개변수), 개방 어휘 검출기 OWLv2(약 1.5억), 언어 모델 Qwen2.5-0.5B/1.5B-Instruct(2권 14장의 그 모델)예요. 각 모델 카드에 적힌 라이선스는 모두 Apache-2.0으로, 상업적 사용을 허락합니다. 10장에서 말했듯 모델을 제품에 넣을 때는 코드, 가중치, 학습 데이터의 조건을 직접 읽어 보세요. 이 장 19.6절의 VLA 표에는 라이선스가 다른 모델도 나옵니다. 예제는 파이썬 3.12, MuJoCo 3.17, transformers 5.20, PyTorch 2.14에서 CPU로 실행해 확인했어요.

## 19.1 파운데이션 모델: 미리 크게 배워 두기

### 백과사전을 읽고 온 신입

새로 온 동료 두 사람을 떠올려 봅시다. 한 사람은 우리 가게의 메뉴 열 개만 외우고 왔고, 다른 사람은 요리책 수천 권을 읽고 왔어요. 첫날에는 둘 다 우리 가게 일을 모릅니다. 하지만 "오늘은 처음 보는 버섯 요리를 해 볼까?"라고 하면 두 번째 사람이 훨씬 빨리 따라오겠죠.

파운데이션 모델이 두 번째 사람입니다. 인터넷 규모의 글, 사진과 설명 글의 짝, 로봇 시연 기록처럼 **아주 큰 데이터로 미리 학습해 두고**, 여러 가지 일에 그대로 쓰거나 조금만 더 가르쳐서 쓰는 모델이에요. 2권 10장의 전이 학습에서 ImageNet으로 미리 학습한 ResNet을 가져와 머리만 바꿔 썼던 것, 2권 14장에서 Qwen2.5에게 프롬프트만으로 여러 일을 시켰던 것이 모두 이 생각에서 나왔습니다. 크기와 데이터가 커지면서 "처음 보는 일도 말로 설명하면 어느 정도 해내는" 능력이 생겼고, 그래서 다른 모델의 바탕(foundation)이 된다는 뜻으로 이런 이름이 붙었어요.

로봇에서 쓰는 파운데이션 모델은 무엇을 받아 무엇을 내놓느냐에 따라 크게 네 갈래로 나눌 수 있습니다.

| 갈래 | 받는 것 | 내놓는 것 | 로봇에서 하는 일 | 이 장에서 |
|---|---|---|---|---|
| 언어 모델(LLM) | 글 | 글 | 지시를 이해하고 계획 세우기 | Qwen2.5(19.5절), Claude(19.8절) |
| 비전-언어 모델(VLM) | 사진 + 글 | 글 | 장면을 설명하고 질문에 답하기 | SmolVLM(19.3절) |
| 개방 어휘 검출기 | 사진 + 찾을 것의 이름(글) | 상자와 점수 | 말한 물체를 사진에서 찾기 | OWLv2(19.4절) |
| VLA(비전-언어-행동) | 사진 + 글 + 로봇 상태 | 로봇 행동 | 보고 듣고 바로 움직이기 | 개념과 판단(19.6절) |

### 이름표가 정해진 눈

9장 9.8절의 검출기는 왜 빨간 원기둥은 컵이라고 하면서 초록 상자는 신호등이라고 했을까요? 그 검출기가 아는 이름부터 확인해 봅시다. 가중치 정보에 들어 있어서 내려받지 않아도 읽을 수 있어요.

```python
from torchvision.models import detection

# 9장 9.8절의 검출기가 아는 이름표(가중치를 내려받지 않아도 읽을 수 있다)
범주 = detection.FasterRCNN_MobileNet_V3_Large_FPN_Weights.COCO_V1.meta["categories"]
이름들 = [이름 for 이름 in 범주 if 이름 not in ("__background__", "N/A")]
print(f"아는 이름 {len(이름들)}개:", ", ".join(이름들[40:48]), "...")
for 낱말 in ["cup", "bowl", "sports ball", "box", "red box", "blue bowl", "robot arm"]:
    print(f"  {낱말!r:14} → {'있음' if 낱말 in 이름들 else '없음'}")
```

```text
아는 이름 80개: wine glass, cup, fork, knife, spoon, bowl, banana, apple ...
  'cup'          → 있음
  'bowl'         → 있음
  'sports ball'  → 있음
  'box'          → 없음
  'red box'      → 없음
  'blue bowl'    → 없음
  'robot arm'    → 없음
```

이 검출기는 80개 이름 중에서만 골라 답합니다. 컵(cup), 그릇(bowl), 공(sports ball)은 있지만 **상자(box)라는 이름이 아예 없어요.** 초록 상자를 신호등이라고 한 것도 "80개 중에서는 그나마 이게 비슷하다"는 답이었던 셈입니다. "빨간 상자", "파란 그릇"처럼 색과 이름을 함께 묻는 것은 처음부터 불가능하고요.

이렇게 정해진 이름표 안에서만 답하는 방식을 **닫힌 어휘(closed vocabulary)** 라고 합니다. 공장처럼 다루는 물건이 정해진 곳에서는 충분하지만, 사람이 아무 말로나 시키는 집안에서는 부족하죠. 이 장의 눈은 이름표를 미리 정하지 않습니다. 찾을 것을 **글로** 받아요.

## 19.2 이 장의 장면

15장의 집게 단 6자유도 팔 앞 탁자에 물체 네 개와 파란 그릇을 놓겠습니다. 빨간 상자는 15장의 그 상자(8×5×5cm)이고, 같은 빨간색의 공을 일부러 옆에 두었어요. 9장처럼 색만 보면 둘을 구별할 수 없게 하려는 것입니다. 파란 그릇은 15장의 놓을 곳 자리에 탁자와 붙여 두었고, 바닥판 하나와 짧은 벽 조각 16개를 둥글게 세워 만들었어요.

카메라는 탁자 앞쪽 위에서 로봇 쪽을 내려다봅니다. 9장의 머리 카메라처럼 9장의 `바라보기` 함수로 방향을 정했어요. 사진을 찍을 때는 팔을 뒤로 돌려 카메라 앞을 비웁니다. 팔과 집게, 상태 기계는 15장의 `팔집게장면.py`, `집게.py`, `잡기도구.py`, `경로도구.py`, `집고놓기.py`를 그대로 복사해 썼어요.

```python
"""19장: 15장의 집게 단 팔 앞 탁자에 물체 넷과 파란 그릇을 놓고, 머리 카메라로 찍는다."""
import mujoco
import numpy as np

from 집게 import 집게_몸체, 집게_부속
from 팔도구 import 예제_팔
from 팔집게장면 import 글, 받침_위치

높이, 너비 = 480, 640                        # 사진 크기(픽셀)
카메라_fovy = 50                             # 머리 카메라의 세로 시야각(도)
카메라_위치 = np.array([0.95, 0.0, 0.95])     # 탁자 앞쪽 위에서 로봇 쪽을 내려다본다
카메라_목표 = np.array([0.38, -0.02, 0.40])
R_광학_mj = np.diag([1, -1, -1])            # MuJoCo 카메라 축 ↔ 광학 축(9장 9.2절)
탁자_높이 = 받침_위치[2]                      # 0.4m

# 이름 → (모양, 반크기(m), 색 rgba, 탁자 위 (x, y), 요(도)). 반크기는 MuJoCo size 그대로
물체들 = {
    "빨간 상자": ("box", [0.04, 0.025, 0.025], "0.85 0.12 0.1 1", (0.42, 0.12), 30),
    "초록 상자": ("box", [0.035, 0.025, 0.03], "0.15 0.65 0.2 1", (0.52, -0.08), -20),
    "빨간 공": ("sphere", [0.03], "0.85 0.12 0.1 1", (0.32, 0.12), 0),
    "노란 컵": ("cylinder", [0.025, 0.04], "0.95 0.8 0.1 1", (0.62, 0.18), 0),
}
그릇_중심 = np.array([0.3, -0.25])           # 15장의 놓을 곳 자리에 둥근 그릇을 붙여 둔다
그릇_반지름, 그릇_벽_높이 = 0.08, 0.04


def 바라보기(위치, 목표) -> np.ndarray:
    """위치에서 목표를 보는 카메라의 R_세계_광학(9장). 사진 아래쪽이 세계 아래쪽을 향한다."""
    z = np.asarray(목표, float) - 위치
    z /= np.linalg.norm(z)
    x = np.cross(z, [0, 0, 1])
    x /= np.linalg.norm(x)
    return np.column_stack([x, np.cross(z, x), z])


def 물체_xml(이름: str, 모양: str, 반크기, 색: str, 위치, 요: float) -> str:
    z = 탁자_높이 + (반크기[0] if 모양 == "sphere" else 반크기[-1])     # 바닥이 탁자에 닿게
    return (f'<body name="{이름}" pos="{글(위치)} {z}" euler="0 0 {요}"><freejoint/>'
            f'<geom name="{이름}" type="{모양}" size="{글(반크기)}" mass="0.1" rgba="{색}" contype="1" '
            f'friction="0.5 0.005 0.0001"/></body>')


def 그릇_xml() -> str:
    """바닥판 하나와 짧은 벽 조각 16개로 만든 둥근 그릇(탁자에 붙어 있다)."""
    벽들 = "".join(f'<geom type="box" size="0.005 0.017 {그릇_벽_높이 / 2}" pos="{그릇_반지름 * np.cos(각):.4f} '
                  f'{그릇_반지름 * np.sin(각):.4f} {그릇_벽_높이 / 2}" euler="0 0 {np.rad2deg(각):.2f}"/>'
                  for 각 in np.linspace(0, 2 * np.pi, 16, endpoint=False))
    return (f'<body name="그릇" pos="{글(그릇_중심)} {탁자_높이}"><geom name="그릇_바닥" type="cylinder" '
            f'size="{그릇_반지름} 0.0025" pos="0 0 0.0025"/>{벽들}</body>')


def 장면_xml(물체=물체들) -> str:
    몸체들 = []
    for i, (_, 위치, 축) in enumerate(예제_팔):
        다음 = 예제_팔[i + 1][1] if i + 1 < len(예제_팔) else [0, 0, 0.03]
        몸체들.append(f'<body name="link{i + 1}" pos="{글(위치)}" gravcomp="1"><joint name="joint{i + 1}" '
                    f'axis="{글(축)}"/><geom type="capsule" fromto="0 0 0 {글(다음)}" size="0.02" rgba="0.8 0.5 0.2 1"/>')
    R_mj = 바라보기(카메라_위치, 카메라_목표) @ R_광학_mj
    return f"""
<mujoco model="말로 시키는 팔">
  <option timestep="0.002" integrator="implicitfast" cone="elliptic" impratio="10"/>
  <visual><global offwidth="{너비}" offheight="{높이}"/></visual>
  <asset>
    <texture type="skybox" builtin="gradient" rgb1="0.95 0.95 1" rgb2="0.6 0.7 0.8" width="256" height="256"/>
    <texture name="격자" type="2d" builtin="checker" rgb1="0.25 0.3 0.35" rgb2="0.75 0.75 0.75" width="256" height="256"/>
    <material name="바닥재" texture="격자" texrepeat="8 8"/>
  </asset>
  <default>
    <joint type="hinge" damping="1" armature="0.05"/>
    <geom contype="2" conaffinity="1"/>
    <position kp="400" dampratio="1"/>
    <default class="그릇"><geom contype="1" rgba="0.15 0.35 0.85 1"/></default>
  </default>
  <worldbody>
    <light pos="0.6 -0.4 2.5" dir="-0.1 0.15 -1" diffuse="0.8 0.8 0.8"/>
    <camera name="머리" pos="{글(카메라_위치)}" xyaxes="{글(R_mj[:, 0])} {글(R_mj[:, 1])}" fovy="{카메라_fovy}"/>
    <geom name="floor" type="plane" size="2 2 0.1" material="바닥재" contype="1"/>
    <geom name="table" type="box" pos="0.35 0 0.2" size="0.45 0.5 0.2" rgba="0.75 0.6 0.45 1"
          contype="1" friction="0.5 0.005 0.0001"/>
    <body name="base" pos="{글(받침_위치)}">
      <geom type="cylinder" fromto="0 0 0 0 0 0.1" size="0.05" rgba="0.3 0.3 0.3 1"/>
      {"".join(몸체들)}{집게_몸체("0 0 0.05")}{"</body>" * len(예제_팔)}
    </body>
    {"".join(물체_xml(이름, *값) for 이름, 값 in 물체.items())}
    <frame childclass="그릇">{그릇_xml()}</frame>
  </worldbody>
  <actuator>
    {"".join(f'<position name="joint{i + 1}" joint="joint{i + 1}"/>' for i in range(len(예제_팔)))}
  </actuator>
  {집게_부속()}
</mujoco>"""


def 찍기(모델: mujoco.MjModel, 데이터: mujoco.MjData) -> tuple[np.ndarray, np.ndarray]:
    """팔을 뒤로 돌려 카메라 앞을 비우고 컬러 사진과 깊이(광학 z, m)를 함께 찍는다."""
    데이터.qpos[:6] = np.deg2rad([180, 30, 90, 0, 60, 0])
    mujoco.mj_forward(모델, 데이터)
    with mujoco.Renderer(모델, 높이, 너비) as 그리개:
        그리개.update_scene(데이터, camera="머리")
        컬러 = 그리개.render()
        그리개.enable_depth_rendering()
        그리개.update_scene(데이터, camera="머리")
        깊이 = 그리개.render()
    return 컬러, 깊이
```

물체마다 `<freejoint/>`가 있어 집어 옮길 수 있고, 그릇은 탁자에 붙은 몸체입니다. `찍기`는 9장처럼 같은 카메라로 컬러 사진과 깊이 사진을 함께 찍어요. 장면을 한 번 찍어 봅시다.

## 19.3 비전-언어 모델로 장면 묻기

### 사진도 토큰이 된다

비전-언어 모델(VLM, vision-language model)은 사진을 보고 글로 답하는 모델입니다. 속을 들여다보면 2권에서 본 부품 두 개를 이어 붙인 모양이에요. 사진을 작은 조각으로 잘라 각 조각을 벡터로 바꾸는 **비전 인코더**(2권 10장의 ViT 같은 것)와, 2권 12장의 트랜스포머로 된 **언어 모델**입니다. 사진 조각 벡터들을 언어 모델이 읽을 수 있는 크기로 바꿔 글 토큰 앞에 끼워 넣으면, 언어 모델은 사진을 "아주 긴 문장의 앞부분"처럼 읽고 그다음 글을 이어 씁니다. 2권 14장에서 본 "다음 토큰 예측" 그대로예요.

이 장에서는 Hugging Face가 공개한 **SmolVLM-500M-Instruct**를 씁니다. 이름처럼 약 5억 매개변수로, 노트북 CPU에서도 몇 초 만에 답하는 작은 모델이에요. 불러오기와 묻기를 `시각언어.py`에 모아 두겠습니다.

```python
"""19장: 작은 비전-언어 모델(SmolVLM)에게 사진을 보여 주고 묻는다."""
import numpy as np
import torch
from PIL import Image
from transformers import AutoModelForImageTextToText, AutoProcessor

모델_이름 = "HuggingFaceTB/SmolVLM-500M-Instruct"     # Apache-2.0, 약 5억 매개변수


def 불러오기() -> tuple:
    처리기 = AutoProcessor.from_pretrained(모델_이름)
    모델 = AutoModelForImageTextToText.from_pretrained(모델_이름, dtype=torch.float32).eval()   # CPU
    return 처리기, 모델


def 묻기(처리기, 모델, 사진: np.ndarray, 질문: str, 최대_토큰: int = 60) -> tuple[str, int]:
    """사진 한 장과 질문 하나. (답, 모델에 들어간 토큰 수)를 돌려준다. 늘 같은 답이 나오게 탐욕 디코딩."""
    대화 = [{"role": "user", "content": [{"type": "image"}, {"type": "text", "text": 질문}]}]
    글 = 처리기.apply_chat_template(대화, add_generation_prompt=True)
    입력 = 처리기(text=글, images=[Image.fromarray(사진)], return_tensors="pt")
    with torch.inference_mode():
        출력 = 모델.generate(**입력, max_new_tokens=최대_토큰, do_sample=False)
    길이 = 입력["input_ids"].shape[1]
    return 처리기.batch_decode(출력[:, 길이:], skip_special_tokens=True)[0].strip(), 길이
```

`do_sample=False`는 2권 14장 14.3절의 탐욕 디코딩입니다. 매번 가장 그럴듯한 토큰만 골라서, 같은 사진과 질문에는 늘 같은 답이 나와요. 먼저 사진을 설명해 달라고 해 봅시다.

```python

from 시각언어 import 모델_이름, 묻기, 불러오기
from 지시장면 import 장면_xml, 찍기

모델 = mujoco.MjModel.from_xml_string(장면_xml())
데이터 = mujoco.MjData(모델)
사진, _ = 찍기(모델, 데이터)

처리기, vlm = 불러오기()
print(f"{모델_이름}: 매개변수 {sum(p.numel() for p in vlm.parameters()):,}개")
답, 길이 = 묻기(처리기, vlm, 사진, "Describe this image.", 최대_토큰=80)
print(f"모델에 들어간 토큰 {길이}개(질문 글은 몇 개뿐, 나머지는 사진)")
print("답:", 답)
```

질문은 영어 몇 단어인데 모델에 들어간 토큰은 874개입니다. 거의 전부가 사진 조각이에요. 사진 한 장이 긴 글 한 편만큼의 자리를 차지한다는 뜻이고, VLM이 같은 크기의 언어 모델보다 느린 이유이기도 합니다.

답은 그럴듯하게 시작합니다. 단순한 도형 장면이라는 것, 색과 모양으로 구별된다는 것은 맞혔어요. 하지만 "네 개의 도형"이라고 했는데 탁자 위에는 다섯 개가 있고, 첫 항목으로 든 "파란 원기둥"은 그릇입니다. 80토큰에서 잘라서 목록은 끝까지 보이지 않아요.

- 바나나는 없다고 했고(맞음), 그릇 색은 파랑, 빨간 물체는 두 개(상자와 공)라고 했습니다. 모두 맞아요.

> **Q. 합성 장면이라서 못 알아보는 걸까요?**
> 일부는 그렇습니다. 9장 9.8절과 10장 10.4절에서 사람이 찍은 사진으로 학습한 모델이 매끈한 합성 도형을 잘 못 알아보는 것을 봤죠. 이 장의 모델들도 진짜 사진으로 학습했어요. 그래도 9.8절의 검출기와 달리 "상자", "공", "그릇"이라는 말을 알고 색도 대체로 맞히는 것은, 학습한 데이터가 훨씬 크고 다양하기 때문입니다. 반대로 시뮬레이터에서 학습한 것을 진짜 세상에 쓰는 문제는 20장에서 다룹니다.

## 19.4 개방 어휘 검출: 글로 찾을 물체 정하기

### 글과 사진을 같은 공간에

말한 물체를 사진에서 찾으려면 어떻게 해야 할까요? 생각은 이렇습니다. 사진의 각 조각을 벡터로 바꾸고, "a red box"라는 글도 같은 길이의 벡터로 바꿉니다. 그리고 둘이 얼마나 같은 방향을 가리키는지(내적)를 점수로 삼아요. 인터넷에서 모은 수억 쌍의 "사진과 그 설명 글"로, 짝이 맞는 사진 조각과 글은 가깝게, 짝이 아닌 것은 멀게 학습해 두면, 처음 보는 이름으로도 물체를 찾을 수 있습니다. 2권 13장의 임베딩이 "뜻이 비슷한 낱말은 가까운 화살표"였던 것처럼, 여기서는 **글과 사진 조각이 한 공간의 화살표**가 되는 거예요.

이 생각으로 만든 검출기를 **개방 어휘 검출기(open-vocabulary detector)** 라고 부릅니다. 이 장에서는 구글이 공개한 **OWLv2**(owlv2-base-patch16-ensemble, Apache-2.0)를 씁니다. 사진을 16픽셀 조각으로 나눠 조각마다 상자 하나와 글 비교용 벡터 하나를 내놓아요. 검출기를 감싸는 클래스와, 9장의 역투영으로 상자 안의 점을 3차원으로 바꿔 크기와 방향을 재는 함수를 `찾기도구.py`에 모았습니다.

```python
"""19장: 글로 지정한 물체를 사진에서 찾고(OWLv2), 깊이로 3차원 위치·방향·크기를 잰다."""
import mujoco
import numpy as np
import torch
from PIL import Image
from transformers import AutoProcessor, Owlv2ForObjectDetection

from 지시장면 import R_광학_mj, 높이, 너비, 탁자_높이

검출기_이름 = "google/owlv2-base-patch16-ensemble"     # Apache-2.0, 약 1.5억 매개변수


class 개방어휘검출기:
    def __init__(self):
        self.처리기 = AutoProcessor.from_pretrained(검출기_이름)
        self.모델 = Owlv2ForObjectDetection.from_pretrained(검출기_이름).eval()   # CPU: 결과를 고정한다

    def 찾기(self, 사진: np.ndarray, 글들: list[str], 문턱: float = 0.1) -> dict[str, tuple]:
        """글마다 가장 점수 높은 상자 하나: {글: (점수, [x1, y1, x2, y2])}. 문턱 아래면 빠진다."""
        그림 = Image.fromarray(사진)
        입력 = self.처리기(text=[글들], images=그림, return_tensors="pt")
        with torch.inference_mode():
            출력 = self.모델(**입력)
        결과 = self.처리기.post_process_grounded_object_detection(
            출력, threshold=문턱, target_sizes=[(그림.height, 그림.width)], text_labels=[글들])[0]
        찾은것: dict[str, tuple] = {}
        for 상자, 점수, 글 in zip(결과["boxes"].tolist(), 결과["scores"].tolist(), 결과["text_labels"]):
            if 글 not in 찾은것 or 점수 > 찾은것[글][0]:
                찾은것[글] = (점수, 상자)
        return 찾은것


def 점구름(모델: mujoco.MjModel, 데이터: mujoco.MjData, 깊이: np.ndarray) -> np.ndarray:
    """깊이 사진의 픽셀마다 세계 기준 3차원 점(높이×너비×3). 9장의 역투영과 변환 사슬."""
    f = (높이 / 2) / np.tan(np.deg2rad(모델.cam("머리").fovy[0]) / 2)
    v, u = np.indices(깊이.shape)
    점_광학 = np.stack([(u - (너비 - 1) / 2) / f * 깊이, (v - (높이 - 1) / 2) / f * 깊이, 깊이], axis=-1)
    R_세계_광학 = 데이터.cam("머리").xmat.reshape(3, 3) @ R_광학_mj
    return 점_광학 @ R_세계_광학.T + 데이터.cam("머리").xpos


def 상자_재기(점들: np.ndarray, 상자, 반경: float = 0.06) -> dict | None:
    """검출 상자 안의 점에서 물체 윗면을 골라 가운데·요·크기를 잰다(15장 15.3절의 주성분 분석).
    반경: 가운데에서 이만큼(m) 안의 점만 쓴다. 상자에 걸친 이웃 물체의 점을 덜어 낸다."""
    x1, y1, x2, y2 = (int(round(값)) for 값 in 상자)
    안 = 점들[max(y1, 0):y2, max(x1, 0):x2].reshape(-1, 3)
    위 = 안[안[:, 2] > 탁자_높이 + 0.01]                       # 탁자보다 1cm 넘게 높은 점
    if len(위) < 20:
        return None
    가운데 = np.median(위[:, :2], axis=0)
    위 = 위[np.linalg.norm(위[:, :2] - 가운데, axis=1) < 반경]
    윗면_높이 = np.percentile(위[:, 2], 90)
    윗면 = 위[위[:, 2] > 윗면_높이 - 0.005][:, :2]
    중심 = 윗면.mean(axis=0)
    _, 고유벡터 = np.linalg.eigh(np.cov((윗면 - 중심).T))
    긴축 = 고유벡터[:, 1]
    투영 = (윗면 - 중심) @ 고유벡터
    return {"중심": np.array([*중심, (탁자_높이 + 윗면_높이) / 2]),    # 윗면과 탁자의 한가운데 높이
            "요_도": float(np.rad2deg(np.arctan2(긴축[1], 긴축[0]))),
            "길이": float(np.ptp(투영[:, 1])), "폭": float(np.ptp(투영[:, 0])),
            "높이": float(윗면_높이 - 탁자_높이)}
```

`점구름`은 9장 9.4절의 역투영과 9.2절의 축 바꾸기(`diag(1, -1, -1)`)를 사진 전체에 한 번에 한 것이고, `상자_재기`는 15장 15.3절에서 점구름 윗면으로 상자의 가운데와 방향, 크기를 찾던 방법을 검출 상자 안의 점에만 적용한 것입니다. 왜 이웃 물체의 점을 덜어 내는지는 곧 보게 돼요.

## 19.5 말을 계획으로: 정해진 기술의 순서

### 메뉴판에 있는 것만 주문받는다

식당에서 "오늘 기분이 별로인데 뭔가 따뜻한 거"라고 주문하면, 직원은 그 말을 메뉴판의 "된장찌개 하나"로 바꿔 주방에 넘깁니다. 주방은 메뉴판에 있는 요리만, 정해진 방법대로 만들어요. 손님의 말이 아무리 자유로워도 주방이 하는 일은 정해져 있습니다.

로봇도 같은 구조로 만들 수 있습니다. 15장의 집고-놓기처럼 **검증된 기술(skill)** 몇 가지를 준비해 두고, 말로 한 지시를 그 기술들의 순서, 즉 **계획(plan)** 으로 바꾸는 거예요. 이 장의 기술은 둘입니다.

| 기술 | 하는 일 | 몸에서는 |
|---|---|---|
| 집기(대상) | 물체 하나를 집어 든다 | 15장 상태 기계의 접근~들기 |
| 놓기(대상) | 들고 있는 물체를 장소에 내려놓는다 | 옮기기~물러나기 |

"빨간 상자를 파란 그릇에 넣어 줘"는 `집기(빨간 상자) → 놓기(파란 그릇)`이 됩니다. 말을 계획으로 바꾸는 쪽은 틀릴 수 있지만, 기술 자체는 15장에서 스무 번 시험한 코드 그대로예요. 언어 모델이 관절 각도를 직접 정하게 하는 것보다 훨씬 안전하죠.

### 규칙으로 바꾸기

가장 단순한 방법부터 해 봅시다. 지시에서 장면의 이름을 찾고, "그릇에"처럼 장소 이름 뒤에 "에"가 붙은 것을 놓을 곳으로, 나머지를 옮길 물체로 봅니다. "공"처럼 장면에 하나뿐인 물건은 색을 빼고 말해도 알아듣게 했어요. 같은 파일에 계획을 검사하는 함수도 함께 두었는데, 검사는 조금 뒤에 설명합니다.

```python
"""19장: 말로 한 지시를 정해진 기술의 순서(계획)로 바꾸고, 실행하기 전에 검사한다."""
import re

import numpy as np

from 잡기도구 import TCP_포즈, 역기구학, 집기_포즈
from 집게 import 손가락_최대
from 집고놓기 import 들기_높이
from 팔집게장면 import 집_자세

기술들 = {"집기": "물체 하나를 집어 든다", "놓기": "들고 있는 물체를 장소에 내려놓는다"}
놓을_곳들 = {"파란 그릇"}                     # 놓기의 대상이 될 수 있는 것
옮기는_말 = ("넣", "담", "놓", "올려", "옮겨")    # 규칙 계획기가 아는 동사의 앞부분
최대_단계 = 8
집을_수_있는_폭 = 2 * 손가락_최대 - 0.01         # 손가락을 다 벌려도 1cm 남아야 한다


def 이름_찾기(지시: str, 이름들: list[str]) -> list[str]:
    """지시에 나온 물체 이름을 나온 순서대로. '공'처럼 하나뿐인 물건은 색을 빼고 말해도 된다."""
    찾은것 = {지시.find(이름): 이름 for 이름 in 이름들 if 이름 in 지시}
    for 물건 in {이름.split()[-1] for 이름 in 이름들}:
        후보 = [이름 for 이름 in 이름들 if 이름.endswith(물건)]
        if len(후보) == 1 and 후보[0] not in 찾은것.values() and (위치 := 지시.find(물건)) >= 0:
            찾은것[위치] = 후보[0]
    return [찾은것[위치] for 위치 in sorted(찾은것)]


def 규칙_계획(지시: str, 이름들: list[str]) -> list[dict]:
    """'무엇(들)을 어디에 넣어' 꼴만 알아듣는 규칙 계획기. 모르면 빈 계획을 낸다."""
    if not any(말 in 지시 for 말 in 옮기는_말):
        return []
    나온것 = 이름_찾기(지시, 이름들)
    장소 = [이름 for 이름 in 나온것 if 이름 in 놓을_곳들 and re.search(이름.split()[-1] + r"\s*(에|안에|위에)", 지시)]
    물체 = [이름 for 이름 in 나온것 if 이름 not in 장소]
    if len(장소) != 1 or not 물체:
        return []
    return [단계 for 이름 in 물체 for 단계 in ({"기술": "집기", "대상": 이름}, {"기술": "놓기", "대상": 장소[0]})]


def 닿나(위치) -> bool:
    """팔이 위치에서 손가락을 아래로 향할 수 있고, 들기 높이까지도 닿는가(역기구학 남은 오차 1mm)."""
    for 위로 in (0.0, 들기_높이):
        T = 집기_포즈(np.asarray(위치) + [0, 0, 위로], 0.0)
        if np.linalg.norm(T[:3, 3] - TCP_포즈(역기구학(T, 집_자세, 반복=200))[:3, 3]) > 0.001:
            return False
    return True


def 계획_검사(계획, 장면: dict[str, dict]) -> list[str]:
    """계획이 지켜야 할 규칙을 모두 확인하고, 어긴 것을 글로 돌려준다. 빈 목록이면 통과."""
    if not isinstance(계획, list) or not 계획:
        return ["계획이 비었거나 목록이 아님"]
    if len(계획) > 최대_단계:
        return [f"단계가 {len(계획)}개로 너무 많음(최대 {최대_단계})"]
    문제들, 든_것 = [], None
    for 번호, 단계 in enumerate(계획, 1):
        기술, 대상 = (단계.get("기술"), 단계.get("대상")) if isinstance(단계, dict) else (None, None)
        if 기술 not in 기술들:
            문제들.append(f"{번호}단계: 모르는 기술 {기술!r}")
        elif 대상 not in 장면:
            문제들.append(f"{번호}단계: 장면에 없는 대상 {대상!r}")
        elif 기술 == "집기":
            if 든_것 is not None:
                문제들.append(f"{번호}단계: 이미 {든_것}을(를) 들고 있음")
            elif 대상 in 놓을_곳들 or 장면[대상]["폭"] > 집을_수_있는_폭:
                문제들.append(f"{번호}단계: {대상}은(는) 집을 수 없음(폭 {장면[대상]['폭'] * 100:.1f}cm)")
            elif not 닿나(장면[대상]["중심"]):
                문제들.append(f"{번호}단계: {대상}까지 팔이 닿지 않음")
            든_것 = 대상
        elif 대상 not in 놓을_곳들:
            문제들.append(f"{번호}단계: {대상}은(는) 놓을 곳이 아님")
        elif 든_것 is None:
            문제들.append(f"{번호}단계: 들고 있는 것이 없음")
        elif not 닿나(장면[대상]["중심"]):
            문제들.append(f"{번호}단계: {대상}까지 팔이 닿지 않음")
        else:
            든_것 = None
    if 든_것 is not None and not 문제들:
        문제들.append(f"끝까지 {든_것}을(를) 들고 있음")
    return 문제들
```

그런데 마지막 줄을 보세요. "초록 상자는 그릇에 넣지 **마**"를 `집기(초록 상자) → 놓기(파란 그릇)`으로 바꿨습니다. "넣"이라는 글자와 이름만 보고 "마"를 무시한 거예요. 규칙은 만든 사람이 생각한 꼴에서는 정확하지만, 생각 못 한 꼴에서는 이렇게 정반대의 일을 할 수 있습니다. 부정, 조건("비어 있으면"), 순서("먼저 ~하고")를 하나씩 규칙으로 더하다 보면 끝이 없어요.

### 작은 언어 모델로 바꾸기

그래서 말을 이해하는 일을 언어 모델에게 맡겨 봅니다. 2권 14장의 Qwen2.5-0.5B-Instruct에게 시스템 프롬프트로 기술 목록과 장면에 있는 것들을 알려 주고, JSON 목록으로만 답하라고 해요. 같은 계열의 1.5B(약 15억 매개변수) 모델과도 비교합니다.

```python
"""19장: 작은 언어 모델(2권 14장의 Qwen2.5)에게 지시를 계획(JSON 목록)으로 바꾸게 한다."""
import json

import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

from 계획도구 import 기술들


class 언어계획기:
    def __init__(self, 이름: str = "Qwen/Qwen2.5-0.5B-Instruct"):     # Apache-2.0
        self.토크나이저 = AutoTokenizer.from_pretrained(이름)
        self.모델 = AutoModelForCausalLM.from_pretrained(이름, dtype=torch.float32).eval()

    def 시스템_글(self, 이름들: list[str]) -> str:
        기술_글 = ", ".join(f"{기술}(대상): {설명}" for 기술, 설명 in 기술들.items())
        return ("너는 로봇 팔의 작업 계획기다. 사람의 지시를 아래 기술의 순서로 바꾼다.\n"
                f"기술: {기술_글}\n장면에 있는 것: {', '.join(이름들)}\n"
                'JSON 목록으로만 답한다. 예: [{"기술": "집기", "대상": "초록 상자"}, {"기술": "놓기", "대상": "파란 그릇"}]')

    def 계획(self, 지시: str, 이름들: list[str]) -> tuple[list | None, str]:
        """(읽어 낸 계획 또는 None, 모델이 쓴 글 그대로). 탐욕 디코딩이라 늘 같은 답이 나온다."""
        대화 = [{"role": "system", "content": self.시스템_글(이름들)}, {"role": "user", "content": 지시}]
        입력 = self.토크나이저.apply_chat_template(대화, add_generation_prompt=True, return_tensors="pt",
                                               return_dict=True)
        with torch.inference_mode():
            출력 = self.모델.generate(**입력, max_new_tokens=120, do_sample=False)
        글 = self.토크나이저.decode(출력[0, 입력["input_ids"].shape[1]:], skip_special_tokens=True).strip()
        try:
            return json.loads(글), 글
        except json.JSONDecodeError:
            return None, 글
```

### 실행 전에 검사하기

누가 만든 계획이든 몸을 움직이기 전에 같은 규칙으로 검사합니다. `계획도구.py`의 `계획_검사`가 확인하는 것은 이렇습니다.

1. 계획이 목록이고, 단계가 8개를 넘지 않는다
2. 기술은 `기술들`에 있는 것(집기, 놓기)만
3. 대상은 카메라가 **실제로 찾은** 물체만
4. 집기는 빈손일 때만, 대상은 집게 너비(8cm)에서 1cm를 뺀 폭보다 좁은 물체만, 팔이 닿는 곳만
5. 놓기는 들고 있을 때만, 대상은 놓을 곳(그릇)만, 팔이 닿는 곳만
6. 끝났을 때 아무것도 들고 있지 않다

"팔이 닿는가"는 거리로 대충 정하지 않고, 15장의 역기구학을 실제로 풀어 봅니다. 손가락을 아래로 향한 채 그 위치와 들기 높이(15cm 위)에 TCP를 둘 수 있는지, 남은 오차가 1mm 안인지 확인해요. 이제 카메라로 잰 장면에서 규칙 계획기와 0.5B 언어 모델의 계획을 함께 검사해 봅시다.

```text
  규칙: 집기(빨간 상자) → 놓기(파란 그릇)
    검사: 통과
  언어 모델: 집기(파란 그릇) → 놓기(빨간 상자)
    검사: 1단계: 파란 그릇은(는) 집을 수 없음(폭 17.0cm) / 2단계: 빨간 상자은(는) 놓을 곳이 아님
[노란 컵이랑 초록 상자를 그릇에 넣어]
  규칙: 집기(노란 컵) → 놓기(파란 그릇) → 집기(초록 상자) → 놓기(파란 그릇)
    검사: 1단계: 노란 컵까지 팔이 닿지 않음
  언어 모델: 집기(노란 컵) → 놓기(초록 상자)
    검사: 1단계: 노란 컵까지 팔이 닿지 않음 / 2단계: 초록 상자은(는) 놓을 곳이 아님
[공을 그릇에 담아]
  규칙: 집기(빨간 공) → 놓기(파란 그릇)
    검사: 통과
  언어 모델: 집기(파란 그릇) → 놓기(초록 상자)
    검사: 1단계: 파란 그릇은(는) 집을 수 없음(폭 17.0cm) / 2단계: 초록 상자은(는) 놓을 곳이 아님
[파란 그릇을 빨간 상자 위에 올려]
  규칙: (빈 계획)
    검사: 계획이 비었거나 목록이 아님
  언어 모델: 집기(파란 그릇) → 놓기(파란 그릇)
    검사: 1단계: 파란 그릇은(는) 집을 수 없음(폭 17.0cm)
```

검사가 제 몫을 했습니다. 규칙 계획기의 "노란 컵이랑 초록 상자" 계획은 문법적으로 멀쩡하지만, 노란 컵까지 팔이 닿지 않아 계획 전체가 거절됐어요. 컵을 집으러 가다가 중간에 멈추는 것보다, 처음부터 움직이지 않는 편이 낫습니다. 언어 모델이 낸 "그릇을 집어 상자에 놓기" 같은 계획도 "파란 그릇은 집을 수 없음(폭 17.0cm)", "빨간 상자는 놓을 곳이 아님"으로 모두 막혔어요.

그런데 언어 모델 줄을 앞의 결과와 비교해 보면 이상한 점이 있습니다. 앞에서 정확히 바꿨던 "빨간 상자를 파란 그릇에 넣어 줘"를 이번에는 `집기(파란 그릇) → 놓기(빨간 상자)`로 거꾸로 바꿨어요. 달라진 것은 시스템 프롬프트의 "장면에 있는 것" 목록 **순서**뿐입니다. 앞에서는 `이름표` 순서(빨간 상자부터)였고, 이번에는 검출기가 찾은 순서(빨간 공, 파란 그릇부터)였어요. 작은 언어 모델의 답은 이렇게 사소한 것에도 흔들립니다.

검사로 막을 수 없는 실수도 있습니다. 앞에서 0.5B가 "창밖으로 던져 줘"를 그릇에 넣는 계획으로 바꾼 것을 떠올려 보세요. 그 계획은 이 검사를 **통과합니다.** 허용된 기술, 보이는 물체, 닿는 곳이니까요. 검사는 계획이 "할 수 있는 일"인지는 확인하지만, "시킨 일"인지는 모릅니다. 그래서 실제 로봇은 계획을 사람에게 "빨간 상자를 집어서 파란 그릇에 놓을게요"처럼 되읽어 주고 확인을 받거나, 시킨 말과 계획을 다시 비교하는 단계를 둡니다.

> **Q. 이 정도 검사면 안전한가요?**
> 아닙니다. 이 검사는 "계획이 말이 되는가"를 보는 첫 번째 울타리일 뿐이에요. 사람이 팔 근처에 들어오면 멈추는 감지, 힘이 이상하면 멈추는 15장의 손목 힘 검사, 손이 닿는 곳의 비상 정지 버튼처럼 계획과 상관없이 몸을 지키는 장치가 따로 있어야 합니다. 로봇 안전은 부록에서 따로 정리합니다. 언어 모델이 무엇을 내놓든, 마지막 결정은 이런 겹겹의 울타리가 해야 해요.

## 19.6 VLA: 보고, 듣고, 바로 움직이는 모델

### 계획 대신 행동을 내놓는다

지금까지 만든 로봇은 일을 나눠서 했습니다. 검출기가 찾고, 계획기가 기술 순서를 정하고, 15장의 상태 기계가 관절 목표를 냈죠. 이 방식은 기술 목록 밖의 일을 못 합니다. 수건 접기, 서랍 열기처럼 "집기"와 "놓기"로 나눠 적기 어려운 일은 기술부터 새로 만들어야 해요.

**VLA(vision-language-action)** 모델은 이 단계를 하나로 합칩니다. 카메라 사진, 지시 글, 로봇의 지금 관절 상태를 받아 **바로 다음 행동**(관절 목표나 손끝 이동량)을 내놓아요. 대개 큰 VLM을 바탕으로 삼아 사진과 말의 뜻은 VLM에게서 물려받고, 로봇 시연 데이터로 행동을 내는 법을 더 가르칩니다. 18장의 모방 학습을 거대한 사전학습 모델 위에서 하는 셈이에요.

행동을 내놓는 방법은 모델마다 다릅니다.

- **행동을 글 토큰으로**: 2023년 구글 딥마인드의 RT-2는 손끝 이동량 같은 숫자를 구간으로 나눠 토큰 번호로 바꾸고, VLM이 글을 쓰듯 행동 토큰을 쓰게 했습니다. 논문 제목이 "웹 지식을 로봇 제어로 옮기는 VLA"였고, VLA라는 이름이 이 논문에서 나왔어요.
- **행동 덩어리를 흐름 맞추기로**: π0와 SmolVLA는 VLM 뒤에 작은 "행동 전문가" 신경망을 달아, 앞으로 수십 걸음의 행동을 한 번에 만듭니다. 18장에서 본 행동 덩어리(action chunk) 그대로이고, 만드는 방법은 2권 15장의 확산 모델과 사촌인 흐름 맞추기(flow matching)예요.

### 공개된 VLA들

대표적인 모델을 공식 자료(논문, 모델 카드, 저장소 안내)로 정리하면 이렇습니다. 매개변수와 라이선스는 아래 코드로 모델 저장소에서 직접 읽은 값이에요.

| 모델 | 발표 | 크기 | 라이선스(모델 카드) | 행동 | 필요한 것 |
|---|---|---|---|---|---|
| RT-2 | 2023, 구글 딥마인드 | 논문에서 가장 큰 것이 550억(55B) | 가중치 공개 안 됨 | 행동을 글 토큰으로 | 사용 불가 |
| OpenVLA | 2024, 스탠퍼드 등 | 약 75억 | MIT (바탕 언어 모델은 Llama 2) | 손끝 이동량 6개와 집게 1개 | 16비트로 약 15GB |
| π0 | 2024, Physical Intelligence | 약 35억 | 코드 Apache-2.0, 가중치 카드는 gemma | 흐름 맞추기, 행동 덩어리 | 추론에 8GB 넘는 NVIDIA GPU(openpi 안내) |

π0의 가중치 카드가 gemma 라이선스인 것은 바탕 VLM인 구글의 PaliGemma에서 조건을 물려받았기 때문입니다. 코드의 라이선스(Apache-2.0)와 가중치의 조건이 다를 수 있다는 10장의 이야기가 여기서도 나오죠. 상업 출판이나 제품에 쓰려면 Gemma 이용 약관까지 읽어야 합니다.

### 이 맥에서 돌릴 수 있을까

크기만 보면 SmolVLA는 이 맥에서 충분히 돌아갑니다. 약 4.5억 매개변수로 이 장에서 쓴 SmolVLM-500M과 비슷하니까요. 하지만 이 장에서는 돌리지 않았습니다. 이유는 세 가지예요.

1. **실행 환경**: SmolVLA는 transformers만으로는 불러올 수 없고 LeRobot 패키지(`lerobot[smolvla]`)가 필요합니다. 이 책의 고정된 예제 환경에는 들어 있지 않아요.
2. **몸이 다르다**: `smolvla_base`는 모델 카드에 "자기 작업에 맞게 미세조정해서 쓰는 바탕 모델"이라고 적혀 있습니다. 우리 팔은 관절 6개에 집게가 따로 있고, 카메라도 한 대예요. OpenVLA의 모델 카드도 "학습 데이터에 없는 새 로봇 몸에는 바로 일반화하지 않으니 시연을 모아 미세조정하라"고 분명히 적어 두었습니다.
3. **행동의 단위**: VLA가 내는 행동은 학습 데이터의 평균과 표준편차로 정규화한 값이라, 그 로봇의 통계로 되돌려야 실제 관절 목표가 됩니다. 우리 팔의 통계는 우리 팔의 시연에서만 나와요.

π0는 저장소 안내대로라면 NVIDIA GPU가 필요하고, OpenVLA는 16비트로도 15GB라 메모리는 들어가지만 마찬가지로 우리 팔을 모릅니다. 정리하면, VLA를 우리 팔에 쓰는 길은 **18장처럼 우리 팔의 시연을 모아 미세조정하는 것**이고, 그 학습은 GPU 서버의 몫입니다. 지금 이 맥에서 할 수 있는 것은 이 장의 방식, 즉 파운데이션 모델로 보고 이해하고, 검증된 기술로 움직이는 것이에요.

두 방식을 나란히 놓으면 이렇습니다.

| | 계획기 + 기술(이 장) | VLA |
|---|---|---|
| 할 수 있는 일 | 기술 목록 안의 일 | 시연으로 배운 일이라면 무엇이든(접기, 닦기 등) |
| 새 로봇에 쓰려면 | 기술만 그 로봇에 맞게 만들면 된다 | 그 로봇의 시연 데이터로 미세조정 |
| 실패를 알아차리기 | 단계마다 조건이 있어 쉽다(15장) | 행동이 바로 나와 어디서 틀렸는지 보기 어렵다 |
| 검사 | 계획을 실행 전에 통째로 검사 | 행동 하나하나에 범위·속도 제한을 걸 수 있을 뿐 |
| 계산 | 작은 모델 몇 개 | 큰 모델 하나를 제어 주기마다 |

실제 제품은 둘을 섞기도 합니다. π0 논문에도 높은 수준의 VLM 정책이 지시를 작은 단계로 쪼개 VLA에게 넘기는 실험이 나와요. 말은 큰 모델이 이해하고, 몸은 잘 배운 정책이 움직이는 구조입니다.

## 19.7 실습: "빨간 상자를 파란 그릇에 넣어 줘"

### 보고, 찾고, 계획하고, 검사하고, 움직이기

이제 조각을 이어 붙입니다. 순서는 이래요.

1. 머리 카메라로 컬러와 깊이를 찍는다 (19.2절)
2. 이름표의 물체를 OWLv2로 찾고, 깊이로 가운데·요·크기를 잰다 (19.4절)
3. 지시를 계획으로 바꾼다. 이 실습에서는 정해진 꼴에 정확했던 규칙 계획기를 쓴다 (19.5절)
4. 계획을 검사한다. 하나라도 걸리면 움직이지 않는다
5. 집기·놓기 한 쌍마다 15장의 상태 기계를 돌린다. 놓을 곳은 그릇 가운데, 높이는 물체가 탁자 위에 있을 때의 가운데 높이로 준다. 15장의 내려놓기는 목표보다 3cm 더 내려가다가 하중이 줄면 멈추니, 그릇 바닥이 조금 높아도 그 자리에서 놓아요

1·2단계와 5단계를 `지시수행.py`에 모았습니다. `집게_요` 함수는 조금 뒤에 설명할게요.

```python
    """이름표의 물체를 사진에서 찾아 {이름: 잰 값}. 찾지 못한 물체는 장면에 없다."""
    점들 = 점구름(모델, 데이터, 깊이)
    장면 = {}
    for 이름, (점수, 상자) in 검출기.찾기(컬러, list(이름표.values())).items():
        이름 = next(한글 for 한글, 영어 in 이름표.items() if 영어 == 이름)
        if (잰 := 상자_재기(점들, 상자, 반경=0.12 if 이름 == "파란 그릇" else 0.06)) is not None:
            장면[이름] = {**잰, "점수": 점수, "상자": 상자}
    return 장면


def 집게_요(이름: str, 장면: dict[str, dict]) -> float:
    """상자는 잰 요 그대로(좁은 쪽을 집는다). 둥근 물체는 요가 의미 없으니,
    손가락이 가장 가까운 이웃 쪽으로 벌어지지 않게 이웃을 향한 방향과 직각으로 벌린다."""
    물체 = 장면[이름]
    if 물체["길이"] - 물체["폭"] > 0.01:
        return 물체["요_도"]
    이웃 = min((값 for 남, 값 in 장면.items() if 남 != 이름),
             key=lambda 값: np.linalg.norm(값["중심"][:2] - 물체["중심"][:2]))
    차이 = 이웃["중심"][:2] - 물체["중심"][:2]
    return float(np.rad2deg(np.arctan2(차이[1], 차이[0])))    # 집게 요 = 이웃 방향이면 손가락은 그 직각으로


def 계획_실행(모델, 데이터, 계획: list[dict], 장면: dict[str, dict], 찍기=None,
            요_정하기=집게_요) -> list[tuple[str, bool, str]]:
    """집기·놓기 한 쌍마다 15장의 상태 기계를 돌린다. 실패하면 거기서 멈춘다."""
    준비(모델, 데이터)
    결과 = []
    for 집기, 놓기 in zip(계획[::2], 계획[1::2]):
        물체, 장소 = 장면[집기["대상"]], 장면[놓기["대상"]]
        놓을_곳 = np.array([*장소["중심"][:2], 물체["중심"][2]])    # 그릇 가운데, 물체 가운데 높이
        q = 데이터.ctrl[:6].copy()
        작업 = 집고놓기(모델, 데이터, 물체["중심"], 요_고르기(물체["중심"], 요_정하기(집기["대상"], 장면), q),
                     놓을_곳, 요_고르기(놓을_곳, 0.0, q), 쥐는_힘=10.0)
        성공 = 작업.실행(최대_시간=데이터.time + 20, 찍기=찍기)
        결과.append((집기["대상"], 성공, 작업.기록[-1][2] or 작업.기록[-1][1]))
        if not 성공:
            break
    return 결과
```

### 공은 왜 집지 못했나

이 실습을 처음 짰을 때 "공을 그릇에 담아"는 실패했습니다. 상태 기계의 기록은 "내려가다 부딪힘"이었어요. 15장 15.8절에서처럼 실패를 다시 만들어 들여다봅시다. 집게의 요를 19.4절에서 잰 값 그대로 쓴 경우와, 지금의 `집게_요`를 쓴 경우를 비교하고, 손가락 패드가 처음 닿은 것을 기록합니다.

```python
import mujoco
import numpy as np

from 계획도구 import 규칙_계획
from 지시수행 import 계획_실행, 장면_읽기, 집게_요
from 지시장면 import 그릇_반지름, 그릇_중심, 장면_xml, 찍기
from 찾기도구 import 개방어휘검출기

검출기 = 개방어휘검출기()
for 방법, 요_정하기 in [("잰 요 그대로", lambda 이름, 장면: 장면[이름]["요_도"]), ("이웃을 피하는 요", 집게_요)]:
    모델 = mujoco.MjModel.from_xml_string(장면_xml())
    데이터 = mujoco.MjData(모델)
    장면 = 장면_읽기(모델, 데이터, 검출기, *찍기(모델, 데이터))
    닿은_곳: dict[str, str] = {}

    def 접촉_보기(작업) -> None:
        """손가락 패드가 무엇에 처음 닿았는지, 그때 어느 단계였는지 모은다."""
        for 접촉 in 데이터.contact[:데이터.ncon]:
            이름들 = {모델.geom(접촉.geom1).name, 모델.geom(접촉.geom2).name}
            if 패드 := {"pad_l", "pad_r"} & 이름들:
                닿은_곳.setdefault(f"{패드.pop()}-{(이름들 - {'pad_l', 'pad_r'}).pop()}", 작업.단계.value)

    결과 = 계획_실행(모델, 데이터, 규칙_계획("공을 그릇에 담아", list(장면)), 장면, 찍기=접촉_보기, 요_정하기=요_정하기)
    공 = 데이터.body("빨간 공").xpos
    print(f"[{방법}] 집게 요 {요_정하기('빨간 공', 장면):6.1f}도 → {결과[0][2]}, "
          f"공이 그릇 안? {np.linalg.norm(공[:2] - 그릇_중심) < 그릇_반지름}")
    print("   손가락이 처음 닿은 것:", ", ".join(f"{짝}({단계})" for 짝, 단계 in sorted(닿은_곳.items())))
```

```text
[잰 요 그대로] 집게 요   80.1도 → 내려가다 부딪힘(6.5N), 공이 그릇 안? False
   손가락이 처음 닿은 것: pad_r-빨간 상자(내려가기)
[이웃을 피하는 요] 집게 요    0.5도 → 완료, 공이 그릇 안? True
   손가락이 처음 닿은 것: pad_l-빨간 공(쥐기), pad_r-빨간 공(쥐기)
```

범인은 19.4절에서 예고한 **공의 요 80.1도**였습니다. 둥근 공에는 긴 쪽이 없으니 이 숫자는 아무 뜻이 없는데, 집게는 그 방향으로 손가락을 벌렸어요. 집게 요가 80도 근처면 손가락이 세계의 x 방향으로 벌어지는데, 공에서 x 방향으로 10cm 옆에 빨간 상자가 있죠. 오른쪽 손가락이 내려가다 빨간 상자에 먼저 닿았고, 15장에서 만든 손목 힘 검사가 바로 알아차려 멈췄습니다.

그래서 `집게_요`는 길이와 폭이 1cm 넘게 차이 나지 않는 둥근 물체라면, 가장 가까운 이웃 쪽을 향해 집게 요를 정합니다. 그러면 손가락은 이웃과 직각 방향으로 벌어져요. 공의 가장 가까운 이웃은 +x 쪽의 빨간 상자라 집게 요가 0.5도가 됐고, 두 손가락이 공에만 닿아 그릇까지 옮겼습니다. 측정값이 "숫자로는 멀쩡하지만 뜻이 없는" 경우를 찾아내는 것, 이것도 파운데이션 모델을 쓰든 안 쓰든 로봇 코드에서 늘 해야 하는 일이에요.

### 다 했는지 사진으로 확인하기

위의 "그릇 안"은 시뮬레이터가 아는 정답으로 판정했습니다. 진짜 로봇에게는 그런 정답이 없어요. 상태 기계가 "완료"라고 해도, 놓는 순간 상자가 그릇 벽에 걸쳐 넘어졌을 수도 있죠. 그래서 일을 마친 뒤 **다시 보고 확인하는** 단계가 필요합니다. 사진에 질문할 수 있는 VLM이 있으니 "빨간 상자가 그릇 안에 있나?"라고 물어보면 어떨까요? 옮기기 전과 뒤에 물어보고, 정답과 나란히 적어 봅시다. 비교를 위해 19.4절의 검출기와 깊이로도 확인합니다.

```python
확인("옮긴 뒤")

# 같은 확인을 검출기와 깊이로: 다시 찍어 빨간 상자를 재고, 옮기기 전에 잰 그릇 가운데와 비교한다
뒤 = 장면_읽기(모델, 데이터, 검출기, *찍기(모델, 데이터))
거리 = np.linalg.norm(뒤["빨간 상자"]["중심"][:2] - 장면["파란 그릇"]["중심"][:2])
print(f"[옮긴 뒤] 잰 빨간 상자와 그릇 가운데 거리 {거리 * 1000:.1f}mm → 그릇 안? {거리 < 그릇_반지름}"
      f" (점수 {뒤['빨간 상자']['점수']:.2f})")
```

```text
[옮기기 전] Is the red box inside the blue bowl? → VLM 'No.', 정답 No
[옮기기 전] Is the green box inside the blue bowl? → VLM 'No.', 정답 No
[옮긴 뒤] Is the red box inside the blue bowl? → VLM 'No.', 정답 Yes
[옮긴 뒤] Is the green box inside the blue bowl? → VLM 'No.', 정답 No
[옮긴 뒤] 잰 빨간 상자와 그릇 가운데 거리 4.4mm → 그릇 안? True (점수 0.25)
```

VLM은 네 번 모두 "No."라고 답했습니다. 네 질문 중 셋은 정답이 No라서, 점수로만 보면 75%를 맞힌 확인기예요. 하지만 정작 알고 싶은 단 한 번, 상자가 그릇에 들어간 뒤의 질문을 틀렸습니다. 늘 같은 답을 하는 확인기는 아무것도 확인하지 않아요. 확인 방법을 시험할 때는 이렇게 **답이 Yes인 경우와 No인 경우를 모두** 넣어 봐야 합니다.

검출기와 깊이로 다시 잰 빨간 상자는 그릇 가운데에서 4.4mm 거리였고, 그릇 반지름 8cm 안이니 "그릇 안"으로 바르게 판정했어요. 그릇 가운데는 **옮기기 전에 잰 값**을 썼다는 점에 주의하세요. 상자가 그릇에 들어간 뒤에 그릇을 다시 재면, 그릇 검출 상자 안에서 가장 높은 윗면이 그릇 테두리가 아니라 빨간 상자 윗면이 되어 그릇 가운데가 상자 쪽으로 끌려갑니다. 이 장의 `상자_재기`는 "검출 상자 안의 가장 높은 면이 그 물체"라고 가정했고, 물체가 겹치면 그 가정이 깨져요.

이 실습의 로봇은 한 번 보고, 계획을 다 세우고, 끝까지 실행했습니다. 1장의 감지·판단·행동 고리로 보면 고리를 한 번만 돈 셈이에요. 물체를 하나 옮길 때마다 다시 찍고, 다시 재고, 남은 계획을 다시 검사하면 고리가 닫힙니다. 15장 실습에서 실패하면 다시 재고 다시 시도했던 것처럼요. 물체가 여럿이고 사람이 중간에 물건을 옮길 수도 있는 21장의 책상 정리에서는 이렇게 매번 다시 보는 구조가 꼭 필요합니다.

이 실습의 계획기는 규칙이라 "넣지 마"에 속는다는 것도 잊지 마세요. 말을 더 잘 이해하는 계획기가 필요하다면 더 큰 언어 모델을 쓰는 것이 자연스러운 다음 걸음입니다. 다음 선택 절에서 해 봅니다.

## 19.8 선택 절: Claude로 지시를 계획하기

이 절은 Anthropic의 API 키가 있어야 실행할 수 있습니다. API는 쓴 만큼 요금을 내는 유료 서비스예요. 키가 없다면 코드를 읽으며 구조만 보고 넘어가도 이 장을 마치는 데 문제가 없습니다. 4권 에이전트 편에서는 이 구조를 훨씬 넓게 다뤄요.

19.5절에서 Qwen2.5에게는 "JSON 목록으로만 답하라"고 부탁했습니다. 부탁이라 자주 어겼죠. Claude API에는 **도구 사용(tool use)** 이라는 기능이 있어서, 우리가 도구(함수)의 이름과 입력 형식을 정해 주면 모델이 글 대신 "이 도구를 이 입력으로 불러 달라"는 요청을 보냅니다. 실제로 도구를 실행하는 것은 우리 코드예요. 그러니 우리의 기술을 도구로 정의하면 됩니다.

설계에서 신경 쓴 점은 이렇습니다.

- **도구는 기술 그대로**: `pick`과 `place` 두 개. 도구 이름에는 영문만 쓸 수 있어 우리 기술 이름과 짝지었다
- **입력을 좁힌다**: 대상은 카메라가 찾은 이름 중에서만 고르게 `enum`으로 정하고, `strict`를 켜서 정의한 형식을 반드시 지키게 한다. 장면에 없는 물체나 지어낸 기술은 형식 단계에서 막힌다
- **부를 때마다 검사**: 도구 호출이 올 때마다 19.5절의 `계획_검사`로 지금까지의 계획에 그 단계를 붙여 보고, 문제가 있으면 거절 이유를 돌려준다. Claude는 이유를 읽고 계획을 고치거나 할 수 없다고 말할 수 있다
- **실행 전에 한 번 더**: 도구 호출 단계에서는 계획을 모으기만 하고, 끝난 뒤 계획 전체를 다시 검사해서 통과해야 15장의 상태 기계를 돌린다
- **키는 환경 변수에서만**: API 키는 코드에 적지 않고 `ANTHROPIC_API_KEY` 환경 변수에서 읽는다. 모델 이름도 맨 위 상수 한 곳에만 둔다
- **주고받기 상한**: 1장의 감시견처럼 주고받는 횟수에 상한을 둔다

```python
import os

import anthropic
import mujoco

from 계획도구 import 계획_검사, 놓을_곳들
from 지시수행 import 계획_실행, 장면_읽기
from 지시장면 import 장면_xml, 찍기
from 찾기도구 import 개방어휘검출기

모델_ID = "claude-sonnet-5-5"           # 쓰는 모델은 여기 한 곳에서만 바꾼다
최대_왕복 = 6                            # Claude와 주고받는 횟수의 상한(1장의 감시견처럼)
도구_기술 = {"pick": "집기", "place": "놓기"}   # 도구 이름은 영문만 된다. 우리 기술 이름과 짝짓는다
시스템 = ("너는 로봇 팔의 작업 계획기다. 사람의 지시를 pick과 place 도구 호출의 순서로 바꾼다. "
         "도구 하나를 부를 때마다 로봇 쪽 검사 결과가 돌아온다. 거절되면 이유를 보고 계획을 고치거나, "
         "할 수 없는 지시면 도구를 부르지 말고 한두 문장으로 까닭을 말한다. 지시에 없는 일은 하지 않는다.")


def 도구_정의(장면: dict[str, dict]) -> list[dict]:
    """대상 이름을 장면에서 찾은 것으로만 고르게(enum) 해서, 없는 물체를 지어내지 못하게 한다."""
    def 도구(이름: str, 설명: str, 대상들: list[str]) -> dict:
        return {"name": 이름, "description": 설명, "strict": True,
                "input_schema": {"type": "object", "properties": {"target": {"type": "string", "enum": 대상들}},
                                 "required": ["target"], "additionalProperties": False}}
    return [도구("pick", "물체 하나를 집어 든다. 한 번에 하나만 들 수 있다.", [n for n in 장면 if n not in 놓을_곳들]),
            도구("place", "들고 있는 물체를 장소에 내려놓는다.", [n for n in 장면 if n in 놓을_곳들])]


def 장면_글(장면: dict[str, dict]) -> str:
    return "\n".join(f"- {이름}: 위치 ({잰['중심'][0]:.2f}, {잰['중심'][1]:.2f})m, 크기 {잰['길이'] * 100:.0f}×"
                     f"{잰['폭'] * 100:.0f}×{잰['높이'] * 100:.0f}cm" for 이름, 잰 in 장면.items())


def 클로드_계획(클라이언트, 지시: str, 장면: dict[str, dict]) -> tuple[list[dict], str]:
    """Claude가 도구를 부를 때마다 우리 규칙으로 검사해 받아들이거나 거절한다. (계획, Claude의 마지막 말)"""
    대화 = [{"role": "user", "content": f"장면(카메라로 잰 값):\n{장면_글(장면)}\n\n지시: {지시}"}]
    계획: list[dict] = []
    for _ in range(최대_왕복):
        응답 = 클라이언트.messages.create(model=모델_ID, max_tokens=16000, system=시스템,
                                       tools=도구_정의(장면), messages=대화)
        if 응답.stop_reason == "refusal":
            return [], "(Claude가 답하지 않음)"
        대화.append({"role": "assistant", "content": 응답.content})
        호출들 = [블록 for 블록 in 응답.content if 블록.type == "tool_use"]
        if not 호출들:
            return 계획, " ".join(블록.text for 블록 in 응답.content if 블록.type == "text")
        결과들 = []
        for 호출 in 호출들:
            단계 = {"기술": 도구_기술.get(호출.name), "대상": 호출.input.get("target")}
            문제들 = [문제 for 문제 in 계획_검사(계획 + [단계], 장면) if not 문제.startswith("끝까지")]
            print(f"   Claude: {호출.name}({단계['대상']}) → {'거절: ' + ' / '.join(문제들) if 문제들 else '받아들임'}")
            if not 문제들:
                계획.append(단계)
            결과들.append({"type": "tool_result", "tool_use_id": 호출.id, "is_error": bool(문제들),
                         "content": "거절: " + " / ".join(문제들) if 문제들 else "받아들임"})
        대화.append({"role": "user", "content": 결과들})
    return 계획, "(주고받기 상한에 닿음)"


if not (키 := os.environ.get("ANTHROPIC_API_KEY")):
    raise SystemExit("ANTHROPIC_API_KEY 환경 변수에 API 키를 넣고 다시 실행하세요.")
클라이언트 = anthropic.Anthropic(api_key=키)
검출기 = 개방어휘검출기()
for 지시 in ["빨간 상자를 파란 그릇에 넣어 줘", "초록 상자는 그릇에 넣지 마",
             "탁자 위 상자를 전부 그릇에 정리해 줘", "노란 컵을 그릇에 넣어"]:
    print(f"[{지시}]")
    모델 = mujoco.MjModel.from_xml_string(장면_xml())
    데이터 = mujoco.MjData(모델)
    장면 = 장면_읽기(모델, 데이터, 검출기, *찍기(모델, 데이터))
    계획, 말 = 클로드_계획(클라이언트, 지시, 장면)
    print(f"   Claude의 말: {말.strip() or '(없음)'}")
    if 계획 and not (문제들 := 계획_검사(계획, 장면)):                # 실행 직전에 계획 전체를 한 번 더 검사
        print("   실행:", [(물체, 메모) for 물체, _, 메모 in 계획_실행(모델, 데이터, 계획, 장면)])
    else:
        print("   실행하지 않음", 문제들 if 계획 else "(계획 없음)")
```

```text
[빨간 상자를 파란 그릇에 넣어 줘]
   Claude: pick(빨간 상자) → 받아들임
   Claude: place(파란 그릇) → 받아들임
   Claude의 말: 빨간 상자를 집어서 파란 그릇에 내려놓았습니다. 두 동작 모두 로봇 검사를 통과했습니다.
   실행: [('빨간 상자', '완료')]
[초록 상자는 그릇에 넣지 마]
   Claude의 말: 지시는 초록 상자를 그릇에 넣지 말라는 금지 명령이라서 로봇이 할 일이 없습니다. 지시에 없는 일은 하지 않으므로 도구를 호출하지 않았고, 초록 상자도 그대로 둡니다.
   실행하지 않음 (계획 없음)
[탁자 위 상자를 전부 그릇에 정리해 줘]
   Claude: pick(빨간 상자) → 받아들임
   Claude: place(파란 그릇) → 받아들임
   Claude: pick(초록 상자) → 받아들임
   Claude: place(파란 그릇) → 받아들임
   Claude의 말: 빨간 상자와 초록 상자를 모두 파란 그릇에 넣었습니다. 로봇 검사도 전부 통과했습니다. 빨간 공과 노란 컵은 상자가 아니라서 건드리지 않았습니다.
   실행: [('빨간 상자', '완료'), ('초록 상자', '완료')]
[노란 컵을 그릇에 넣어]
   Claude: pick(노란 컵) → 거절: 1단계: 노란 컵까지 팔이 닿지 않음
   Claude의 말: 노란 컵을 집을 수 없어서 그릇에 넣지 못합니다. 컵은 (0.62, 0.18)m에 있는데, 로봇 팔이 그 위치까지 닿지 않는다고 거절됐습니다. 제가 쓸 수 있는 동작은 물체를 집는 것과 파란 그릇에 놓는 것뿐입니다. 컵을 팔이 닿는 곳으로 옮길 방법이 없습니다. 컵을 팔이 닿는 위치로 옮겨 주시면 다시 시도하겠습니다.
   실행하지 않음 (계획 없음)
```

지시마다 Claude가 부른 도구, 우리 검사의 판정, Claude의 마지막 말, 실행 결과가 차례로 찍혔습니다. 이 출력은 2026년 10월에 `claude-sonnet-5-5`로 한 번 실행한 것이에요. 언어 모델의 답이라 실행할 때마다 표현이나 도구를 부르는 묶음이 조금씩 다를 수 있습니다. 네 지시를 하나씩 보면 이렇습니다.

- "빨간 상자를 파란 그릇에 넣어 줘"에서는 `pick`과 `place`를 한 번씩 불렀고, 검사를 통과해 19.7절과 같은 집고-놓기가 실행됐다
- "초록 상자는 그릇에 넣지 마"에는 도구를 부르지 않고 할 일이 없다고 말로 답했다. 19.5절의 규칙 계획기와 0.5B 모델은 여기서 상자를 넣으려 했다
- "탁자 위 상자를 전부"에서는 장면의 이름 목록에서 빨간 상자와 초록 상자만 골라냈고, 빨간 공과 노란 컵은 상자가 아니라서 건드리지 않았다고 까닭까지 밝혔다
- 팔이 닿지 않는 노란 컵은 검사가 `pick`을 거절했다. Claude는 거절 이유를 읽고 다른 길을 지어내지 않았고, 컵을 팔이 닿는 곳으로 옮겨 주면 다시 해 보겠다며 사람에게 넘겼다

어느 경우든 Claude는 계획을 **제안**할 뿐이고, 무엇을 실행할지는 우리 검사가 정한다는 점이 이 구조의 핵심입니다. 모델이 아무리 좋아져도 이 순서는 바꾸지 않는 것이 좋아요.

## 19.9 정리와 다음 장 미리보기

이 장에서 로봇에게 말로 일을 시키는 길을 처음부터 끝까지 따라갔습니다.

- **파운데이션 모델**: 큰 데이터로 미리 학습해 여러 일에 쓰는 모델. 로봇에서는 언어 모델, 비전-언어 모델, 개방 어휘 검출기, VLA. 9.8절의 검출기처럼 80개 이름표에 갇힌 닫힌 어휘와 달리, 찾을 것을 글로 받는다
- **비전-언어 모델**: 사진이 수백 개의 토큰이 되어 글 앞에 붙는다. 색, 대략의 배치는 맞히지만 같은 물체를 두고 답이 엇갈리고, 위치를 숫자로 내지 못한다. 답은 측정값이 아니라 말이다
- **개방 어휘 검출**: 글과 사진 조각을 한 공간에서 비교한다. 빨간 상자와 빨간 공을 구별하지만, 점수는 순위로 읽고, 글 표현 하나에 점수가 크게 바뀐다. 장면 이름과 검출기 글을 짝지어 관리한다
- **3차원으로**: 검출 상자 안의 점구름에서 이웃 물체의 점을 덜고 윗면으로 가운데·요·크기를 잰다. 둥근 물체의 요처럼 뜻 없는 숫자를 조심한다
- **말 → 계획**: 정해진 기술(집기, 놓기)의 순서로 바꾼다. 규칙은 정해진 꼴에 정확하지만 "넣지 마"에 속는다. 작은 언어 모델은 형식을 흉내 내지만 기술과 이름을 지어내고, 목록 순서에도 답이 흔들린다
- **검사**: 허용된 기술, 보이는 물체, 집을 수 있는 크기, 역기구학으로 확인한 도달 범위, 빈손·든 손 순서. 통과하지 못하면 움직이지 않는다. 다만 "시킨 일인가"는 검사로 알 수 없으니 사람에게 되읽어 확인한다
- **VLA**: 사진·말·상태에서 바로 행동(행동 덩어리)을 낸다. RT-2, OpenVLA, π0, SmolVLA. 크기와 라이선스가 제각각이고, 새 로봇 몸에는 그 로봇의 시연으로 미세조정해야 한다
- **실습**: 보고, 찾고, 계획하고, 검사하고, 15장의 상태 기계로 움직인다. 정해진 꼴의 지시 넷을 해냈고, 닿지 않는 곳과 모르는 동작은 움직이기 전에 거절했다. 둥근 공의 뜻 없는 요가 손가락을 이웃 상자에 부딪히게 했다. 다 했는지는 다시 보고 확인하는데, 늘 "No"라고 답한 VLM보다 검출기와 깊이가 믿을 만했다

이 장의 모델들은 모두 진짜 사진으로 학습했는데, 우리는 MuJoCo가 그린 사진에 썼습니다. 점수가 0.16~0.72로 들쭉날쭉했고 VLM이 빨간 상자를 두고 엇갈린 답을 한 데에는 이 차이도 한몫했을 거예요. 로봇 학습에서는 반대 방향의 문제가 더 큽니다. 17장의 강화 학습과 18장의 모방 학습은 시뮬레이터 안에서 배웠는데, 그 정책을 진짜 팔에 올리면 마찰도, 무게도, 카메라 사진도, 모터의 늦음도 다릅니다. 다음 20장 sim2real에서는 이 간격을 재고 줄이는 방법, 이를테면 10장에서 이름만 꺼냈던 도메인 무작위화(시뮬레이터의 겉모습과 물리 값을 일부러 흔들며 학습하기)를 다뤄요. 이 장에서 "모델이 학습한 세상과 쓰는 세상이 다르면 무슨 일이 생기는가"를 여러 번 봤으니, 그 경험을 손에 쥐고 넘어가세요.
